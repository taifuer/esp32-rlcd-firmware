# 开发计划

本文只记录尚未进入正式版本的后续方向。已发布功能见
[CHANGELOG](../CHANGELOG.md)，已完成的实机验收见[实机验证记录](bringup-log.md)。

## 下一阶段优先级

### microSD 图片与环境历史

- 评估由浏览器完成裁剪、黑白预览和转换，再上传到 microSD；支持选择当前图片或按小时、
  每天缓慢轮换，但不做快速幻灯片，也不为每个文件增加新页面；
- 温湿度历史记录需要先完成断电恢复、文件轮转、写入寿命和损坏恢复
  设计，不直接放宽现有应用层只读边界；
- microSD 不用于保存音频诊断的临时语音。

### 可选联网与语音能力

- 天气和日程只有在数据来源、配置入口、过期标识与离线缓存都明确后，才考虑进入日常
  页面；网络失败不得阻塞首屏；
- MQTT 或 Home Assistant 可作为开发者集成方向，优先复用现有温湿度、电池和设备状态，
  不为集成入口增加日常页面；
- 离线唤醒词与语音命令属于独立研发方向，需要先验证模型分区、内存、持续监听功耗、
  误唤醒和隐私边界；在没有明确日常指令集前，麦克风继续只用于用户主动发起的设备诊断；
- BLE 只有在手机配网或配套应用形成完整流程时再启用，不为未使用的无线能力增加图标。

后续功能进入实现前，应先确定用户价值、交互位置、离线行为和验收边界；
实现时同步更新设计规范、用户文档、SVG 效果图、主机测试和实机记录。
