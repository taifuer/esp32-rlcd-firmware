# 开发计划

本文记录后续方向与已发布功能待补的专项验证。已发布功能见
[CHANGELOG](../CHANGELOG.md)，已完成的实机验收见[实机验证记录](bringup-log.md)。

## 后续优先级

### 1. 启动恢复与 OTA 健康判定的专项验证

- 同一应用镜像在 60 秒健康门槛前连续发生 3 次异常复位后，下一次启动进入恢复模式；开机
  时按住 `KEY` 也可主动进入。计数只保存在 RTC 保留内存，正常断电、棕断、USB/JTAG
  复位、已标记的更新重启和应用镜像变化不会把旧故障链带入下一次启动；
- 恢复模式只初始化显示、按键、持久化设置、RTC、网络和固件更新所需基础服务，页面只保留
  “在线更新”与“设置”。恢复门户仅提供 Wi-Fi 管理和本地 OTA，不启动天气、音频、
  microSD、温湿度与闹钟等非恢复服务；
- 待验证 OTA 只在正常模式确认显示和按键可用、完成首轮周期任务、成功显示页面并运行至少
  15 秒后确认；确认失败每 5 秒重试。稳定运行满 60 秒才清除异常复位链，恢复模式自身不
  确认待验证镜像；
- v0.25.0 已发布上述实现，但仍需在目标板注入 panic、看门狗和未标记软件复位，验证连续
  3 次后的下一次启动进入恢复、正常断电与计划内 OTA 重启不误触发、开机按住 `KEY` 可
  主动进入、精简门户能
  更换 Wi-Fi 与完成本地
  OTA、按键不可用时自动开放精简门户，以及待验证镜像的延迟确认、失败重试和 Bootloader
  回滚。完成前不得把整体使用反馈记为这些专项场景的实机验收通过。

### 2. 外部仪表功耗与续航基线

- v0.18.0 已实现始终生效的自动低电规则、手动提前省电、20% / 25% 滞回、
  运行期连续两次确认以及 80—240 MHz DFS；连接 USB 数据主机时强制恢复 `NORMAL`。
  v0.19.0 进一步明确 `NORMAL` 使用 `WIFI_PS_MIN_MODEM` 保持家庭 Wi-Fi，`SAVING` 只为
  用户主动操作临时联网；
  原板未向 ESP32 提供 VBUS 或充电状态输入，若以后要求识别墙充或充电宝，需先增加隔离后
  的 VBUS 检测硬件，不能仅靠固件补齐。这些实现项不再列为后续工作，当前缺口是实机电流
  与续航数据；
- 在断开 USB、仅由受控电池供电的统一条件下，使用外部电流表或功耗分析仪分别测量
  `NORMAL` 已连接、`NORMAL` 断网重试、`SAVING | MANUAL` 与 `SAVING | LOW BAT` 的
  稳态电流和工作峰值，并覆盖闹钟开关、microSD 有无、Wi-Fi 任务、设置门户、屏幕刷新和
  音频空闲等状态；
- 记录仪表、供电电压、电池容量、固件版本、测试时长、环境与重复次数。只有取得可复现
  数据后，才根据瓶颈继续处理未使用外设、轮询间隔、Modem-sleep 参数与断线退避，并估算
  实际续航；
- 同时记录拔掉 USB 静置 2—5 分钟、插入 USB 30—60 秒、再次拔线静置 2—5 分钟三组
  GPIO4 还原电压，并用万用表抽查电芯端电压。当前百分比是端电压近似值，不是真实容量；
  充电和负载变化会造成跳动，插线后抬升也不得解释为瞬间充入相应电量。取得实测序列后再
  评估显示侧的跨样本平滑、死区或 5% 粒度，不用电压上升趋势冒充可靠充电状态。需要准确
  荷电状态时必须增加电量计硬件；
- 当前仍不启用 Light-sleep 或 Deep-sleep。Light-sleep 只有在 USB Serial/JTAG、实体按键、
  屏幕刷新、RTC 闹钟、音频、microSD 与 OTA 均有独立实机验收方案后才重新评估；在外部
  仪表数据和确定电池容量齐备前，不承诺固定续航时长、节电百分比或提升倍数。

### 3. 离线语音可靠性基线

- 已准备易失统计、结构化 USB 日志、固定 50 次测试矩阵和串口采集工具；这些开发能力不
  增加用户页面，不保存 PCM，也不能代替目标板上的声学、功耗和报警时序验证；
- 在安静、日常背景声、近距离和较远距离下重复测试固定白名单，记录误接受与拒绝，避免
  用单次识别成功推断整体声学表现；
- 连续执行成功、未识别和取消会话，记录 PSRAM、内部 RAM、任务栈和碎片趋势，并分别
  验证闹钟在准备、监听、识别和结果阶段的抢占；
- 在 `SAVING | MANUAL` 与 `SAVING | LOW BAT` 下测量一次语音会话的电流峰值和 brownout
  风险。没有这些数据前不增加唤醒词、持续监听或更大的模型。

### 4. AI 对话 Beta 后续实机基线

- 使用独立测试 Key，验证启用、停用但保留 Key、空白 Key 保存、清除、正确 Key、错误 Key、
  无权限、无互联网和服务端超时；检查设置状态、屏幕与日志均不泄漏完整 Key、Authorization、
  PCM 或对话正文；
- 分别完成中文、英文、短句、接近 10 秒输入、无声、`KEY` 提前结束和各阶段 `BOOT`
  取消，确认 16 kHz 采集、手动提交、24 kHz 流式播放及错误恢复；分别验证默认
  `qwen3-omni-flash-realtime` 与高级可选 `qwen-audio-3.0-realtime-flash`；分别覆盖北京
  共享、新加坡共享及北京/新加坡 Workspace 专属 Host，确认地域不匹配时安全失败，并拒绝
  scheme、路径、端口、IP、任意域名、独立 Workspace ID、App ID 和任意模型名；
- 使用可观测的连续问答验证 2—5 轮始终复用同一 TLS WebSocket，第 2 轮以后能正确
  利用前文；覆盖播放中 `KEY` 跳过回复并续问、`FOLLOW-UP` 中 `KEY` 继续与
  `BOOT` 结束、第 5 轮自动结束、30 秒续问超时、5 分钟下一轮准入边界和在途回答保护；
- 连续执行至少 20 段成功与失败交错会话，观察内部 RAM、PSRAM、任务栈、codec、Wi-Fi
  和性能锁是否全部回收；验证闹钟抢占后无迟到回复、设置门户与 OTA 仍可正常使用；
- 评估 WebSocket 传输层的敏感 Header 生命周期。应用侧临时缓冲会主动清零，但当前上游
  组件销毁其内部 Header 副本时只释放内存，不保证覆盖旧内容；在不维护大段第三方分支的
  前提下，研究可验证清零的封装或上游修复；
- 在确认当前有界多轮半双工体验、延迟、资源回收和实际账单前，不提高 5 轮、
  30 秒续问或 5 分钟准入边界，不增加唤醒词、后台监听、自动 VAD、全双工、
  自动执行云端命令或跨会话持久历史。

### 5. 温湿度历史设计

- 实现前先确定采样频率、保留时长、屏幕用途、断电恢复、文件轮转、写入寿命、
  损坏恢复与旧分区升级路径；不以仅存内且无过期标识的曲线冒充可靠历史；
- 历史数据不与用户主动发起的 microSD 图片导入和删除事务混用同一写入边界，
  也不得使无卡设备丧失时钟、日历和实时环境数据。

### 6. 天气 Beta 后续验证

- v0.24.0 首次提供独立天气页：首屏继续显示板载 SHTC3 的室内温湿度，天气页只显示
  所选地点的室外实况、三日预报、更新时间和过期状态；功能开启后即加入 `BOOT` 页面环，
  请求中和失败原因都在固定天气布局内显示；
- 设置门户按“省份 → 城市”选择中国大陆地点，并保存用户自己的 QWeather
  API Host 和 API Key。设备通过 HTTPS 直连 QWeather，不经过项目服务器；设置页不回显
  Key，普通保存不重启，并在保存天气配置后打开稳定天气页一次；
- 实时天气约 30 分钟、逐日预报约 6 小时刷新；同地点后台刷新失败时保留最后一次成功缓存，
  `SAVING` 不执行周期天气联网。v0.25.0 在天气页增加按住 `KEY` 2 秒手动刷新，用户
  明确操作时可在 `NORMAL` 或 `SAVING` 为本次请求临时联网；不再使用临时全屏状态页或
  3 秒自动返回。位置目录、响应解析、缓存时效、页面稳定状态与手动刷新门控均需主机测试
  覆盖；
- Beta 阶段仍需继续验证中国大陆网络可达性、证书链、Gzip 与分块响应、真实地点解析、
  缓存跨重启、断网过期显示、设置后即时获取、天气页手动刷新、`NORMAL`/`SAVING` 联网
  收尾、API Key 不回显与错误凭据恢复，并按实际账号核对请求量和账单。

## 暂缓方向

- **BLE**：只有在手机配网或配套应用形成完整流程时再启用，不为未使用的无线能力
  增加开关、图标、功耗和安全面；
- **唤醒与常驻语音**：离线指令和可选 AI 对话 Beta 都只在用户长按后开始；在持续监听功耗、
  误唤醒、唤醒提示、隐私和用户价值完成独立验证前，不增加唤醒词或后台麦克风采集；
- **图片自动轮播**：当前保持“用户选择后持续显示、短按手动切换”，不增加按小时、
  日期或其他周期自动换图的设置；
- **日程与联网集成**：日程只有在数据来源、配置入口、过期标识与离线缓存都明确后才考虑
  进入日常页面；MQTT 或 Home Assistant 仅作为开发者集成候选，
  优先复用现有温湿度、电池和设备状态，不为集成入口增加日常页面。

后续功能进入实现前，应先确定用户价值、交互位置、离线行为和验收边界；
实现时同步更新设计规范、用户文档、SVG 效果图、主机测试和实机记录。
