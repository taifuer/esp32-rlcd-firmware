# 开发计划

本文只记录尚未进入正式版本的后续方向。已发布功能见
[CHANGELOG](../CHANGELOG.md)，已完成的实机验收见[实机验证记录](bringup-log.md)。

## 后续优先级

### 1. 真实功耗测量与低功耗

- 先在电池供电且断开 USB 的统一条件下，分别测量 `NORMAL` 与 `SAVING`
  的稳态电流，并覆盖闹钟开关、microSD 有无、Wi-Fi 任务、设置门户和音频空闲等状态；
- 只根据实测结果处理未使用外设、CPU 频率、轮询间隔和网络收尾；Light-sleep
  必须在 USB Serial/JTAG、实体按键、屏幕刷新、RTC 闹钟、音频与 OTA 都通过实机验证后再考虑；
- 暂不引入 Deep-sleep，不在没有电流数据和确定电池容量时承诺续航时长或提升倍数。

### 2. 温湿度历史设计

- 实现前先确定采样频率、保留时长、屏幕用途、断电恢复、文件轮转、写入寿命、
  损坏恢复与旧分区升级路径；不以仅存内且无过期标识的曲线冒充可靠历史；
- 历史数据不与用户主动发起的 microSD 图片导入和删除事务混用同一写入边界，
  也不得使无卡设备丧失时钟、日历和实时环境数据。

## 暂缓方向

- **BLE**：只有在手机配网或配套应用形成完整流程时再启用，不为未使用的无线能力
  增加开关、图标、功耗和安全面；
- **常驻语音**：在没有明确日常指令集，也未验证模型分区、内存、持续监听功耗、
  误唤醒和隐私边界前，麦克风继续只用于用户主动发起的设备诊断；
- **图片自动轮播**：当前保持“用户选择后持续显示、短按手动切换”，不增加按小时、
  日期或其他周期自动换图的设置；
- **天气、日程与联网集成**：天气和日程只有在数据来源、配置入口、过期标识与
  离线缓存都明确后才考虑进入日常页面；MQTT 或 Home Assistant 仅作为开发者集成候选，
  优先复用现有温湿度、电池和设备状态，不为集成入口增加日常页面。

后续功能进入实现前，应先确定用户价值、交互位置、离线行为和验收边界；
实现时同步更新设计规范、用户文档、SVG 效果图、主机测试和实机记录。
