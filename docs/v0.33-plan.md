# v0.33.0 计时、图片取景与日历空态

2026-10-03，用户确认 `0.33.0-dev.2` 整体使用正常，并授权正式发布 `0.33.0`。
正式版沿用 dev.2 的交互范围；本文件保留开发历史、兼容边界、主机验证与发布记录。
dev.1 与 dev.2 均有独立的主机测试、固定 ESP-IDF 构建和 Beta 公网镜像校验记录。
用户整体反馈不等于所有专项场景逐项通过；长期运行、真实断电、并发提醒和不同浏览器触摸
等未单独记录的实机项继续保留，不以代码检查或构建成功代替实测。

## 范围与交互

### 计时

新增可选日常页 `TIMER`，同一页可显示倒计时或秒表。两者独立运行，切页、切换模式或
隐藏计时入口均不暂停；使用单调时间，不依赖 RTC 校时、Wi-Fi、互联网或 microSD。
不增加后台网络、监听、日志写卡或新的系统菜单，不改变首屏及省电策略。
以下为正式版沿用的 dev.2 规则：开机后倒计时初始选择 5 分钟，停留在 `IDLE` 选择态，不自动开始。
倒计时空闲时在原页选择时长，不新增选择菜单，也不自动选中旧配置中的 25 分钟或其他自定义值。

| 输入 | 行为 |
| --- | --- |
| 倒计时选择态短按 KEY | 循环选择 1、5、10、30 分钟及非重复的门户自定义值，最多 5 档 |
| 倒计时选择态按住 KEY 2 秒 | 开始本次选中的时长 |
| 倒计时运行或暂停时短按 KEY | 暂停或继续，暂停保留进度 |
| 倒计时运行、暂停或完成时按住 KEY 2 秒 | 重置回选择态，保留刚选中的时长，不自动开始 |
| 倒计时完成时短按 KEY | 回到选择态，保留刚选中的时长，不自动重开 |
| 秒表短按 KEY / 按住 KEY 2 秒 | 开始、暂停或继续 / 归零，规则不变 |
| 短按 BOOT | 切到下一可用日常页，两种计时继续 |
| 按住 BOOT 2 秒 | 切换倒计时与秒表显示，不影响另一计时状态 |

网页“常用 → 计时”独立保存 1–180 分钟的自定义候选时长，新装及恢复默认值为 5 分钟。
自定义值与 1、5、10、30 任一档重复时不增加档位，否则作为第五档。设备选择只影响本次计时，
不写 NVS。网页保存仅修改候选档，不改变当前选中时长或运行、暂停、完成状态；重置仍保留
本次选中的时长，而非切到新自定义值。若正在选择的旧自定义档被网页替换，当前选择也保留，
下次短按 KEY 才按新的候选序列选择。恢复偏好默认值遵守同一规则，不取消计时。
dev.2 不增加设置 schema，也不重写已有的 25 分钟或其他合法自定义配置；旧 25 分钟可成为
第五档，但升级或重启后初始仍选择 5 分钟。
秒表显示到秒，在 `99:59:59` 封顶，不回绕、不响铃。运行进度不持久保存；重启后秒表
归零、倒计时回到 5 分钟选择态，自定义偏好仍保留，不自动续计时，也不补发关机期间的提醒。

页面保持大时间、短状态与明确按键提示，不显示毫秒动画或装饰性进度条。长按沿用统一
的 1 秒提示、2 秒触发及松开门控，长按结束不得误执行短按。日常页无无操作返回超时。

### 到期提醒与事务优先级

倒计时到零保持 `DONE`，只发出一次待提醒事件；不关闭设备、不影响另一计时。
可提示时复用 `audio_alert_preview`，按已保存闹钟音量播放最长 3 秒短提示声；0% 时只
显示屏幕，不调用音频试听，也不因提醒停止音乐。有声提醒会先停止正在播放的音乐，
结束后不自动续播，需用户主动播放，避免混音抢声或未经用户操作自行恢复。
完成模态最多显示 10 秒，任意一个新的短按确认关闭并返回原页面；原页面
已隐藏时回到时钟。模态开始前已按住的键先等完整松开，确认不得同时执行底层页面动作。

RTC 闹钟优先。AI/离线语音、OTA、设置门户、写卡等正在进行的事务不能被计时提醒打断；
待提醒最多等待 60 秒，超过后放弃弹出和响铃，计时页继续显示 `DONE`，不在长事务结束后
补响旧通知。提醒显示期间 RTC 闹钟仍可抢占。此提醒不改变 RTC 闹钟规则，也不是音乐
“定时停止”；两项原有功能的资源所有权和行为保持独立。

### 浏览器图片取景

- “完整显示”（`contain`）为默认，保持比例显示完整原图，空白填黑。
- “铺满裁剪”（`cover`）保持比例铺满，鼠标或手机触摸可拖动取景，可回到居中；
  取景受原图边界约束，不拉伸，也不把保留区纳入裁剪内容。
- 可见内容固定为顶部 400 × 250，底部 50 像素始终保留给设备页脚；最终仍为
  400 × 300 黑白 PBM，预览明确标出底部保留区。
- JPEG/PNG 原图、裁剪、阈值调整与二值化只在当前浏览器完成，原图不上传。
  拖动和切模式不发网络请求，只有明确上传才发送最终 PBM；已有卡文件不被静默覆盖。
  现有大小上限、临时文件、格式与摘要校验、去重及受控写卡流程保持不变。

### 日历未校时空态

RTC 无效或日期超出支持范围时，保留 `CALENDAR` 标题、简短原因和网页校时建议，不显示
虚构日期；保留实际 `BOOT` 下一页与 `KEY: SETTINGS` 导航。不再用无页脚的全屏状态页
替代日历，不强制跳页或自动联网。原 v0.32 计划中另行跟踪的此项问题纳入本轮验证。

## 设置与兼容边界

- `APP_PAGE_TIMER` 追加在旧枚举末尾，不改变旧页面 ID；页面 stable ID 为 `1 << 6`
  （64），其他位不变。可选页总数为 7，完整显隐掩码为 127，时钟始终第一位。
- 新装与恢复默认顺序是天气、市场看板、日历、计时、图片、音乐、对话，仍按服务与文件
  可用性跳过。保存排序不抢走当前仍可用页面，显隐、普通导航与模态恢复共用可用性规则。
- 升级保留旧六页显隐和排序，计时追加末尾，不插入用户已有排序中间；旧掩码为 0 时保持
  0，只显示时钟，其余旧掩码保留原位并新增计时可见位。旧记录没有顺序字段时沿用旧六页
  默认顺序后追加计时。
- 通用设置 schema 12 使用新的 `cfg12_a/b`，每条记录为 44 字节；旧 `cfg11_a/b` 及更早
  源记录保留。两份新槽写入成功后才提交 schema 标记；失败可重试，CRC 有效但顺序无效的
  记录也必须拒绝。`timer_minutes` 有界校验为 1–180；dev.2 沿用 schema 12，新增字段缺省值
  及新装/恢复默认值改为 5 分钟，已有 schema 12 中合法的 25 分钟或其他自定义值原样保留。
- 门户使用独立 `section=timer` 表单，只修改计时时长；拒绝重复、未知、混入其他分区的
  字段。旧六项排序表单不能静默补全或重置新页，需重新读取七项完整顺序。
- 除新增计时偏好和页面入口外，原时区、音量、闹钟、音乐模式、手动省电与更新偏好保留；
  Wi-Fi、天气、市场、AI 凭据及 microSD 文件不迁移、不删除。旧固件不认识 schema 12，
  不应在新旧版本间反复编辑偏好；保留旧槽不等于旧固件可以编辑新格式。

## 开发版本沿革

- dev.1 首次加入计时、图片取景与日历空态，设置升级为 schema 12；当时倒计时默认
  25 分钟，短按 KEY 开始/暂停/继续，空闲时长按 KEY 切换 5/10/25/45/60 及自定义时长。

  及用户已有的 25 分钟或其他自定义偏好。正式版采用这套操作，不沿用 dev.1 的旧按键规则。
- 两次候选的镜像、源码摘要与验证记录如下保留，不用正式版本号覆盖历史记录。

## 后续

通用门户设置沿用既有 `get → parse → save` 整份快照保存流程。独立表单限制可提交字段，
但读取与保存之间若实体按键并发修改音量或手动省电，旧快照仍可能覆盖该修改。本轮不扩展
旧通用保存架构；后续应评估锁内合并最新字段，并连同时区应用、失败回滚和并发回归一起验证。
