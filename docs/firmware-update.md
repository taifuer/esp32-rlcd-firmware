# 固件安装与更新

v0.7.0 起使用两个 3 MiB OTA 应用槽。新镜像只写入未运行槽，校验通过后才切换启动目标；
普通更新不覆盖 NVS，因此会保留家庭 Wi-Fi 配置。

下文按 v0.20.0 正式版说明。在线更新与设置门户本地 OTA 使用相同的 `-ota.bin` 和校验
规则。

## 两类发布固件

| 文件后缀 | 用途 | 写入方式 | 是否清除 Wi-Fi |
| --- | --- | --- | --- |
| `-factory.bin` | 首次安装、旧版本迁移和故障恢复 | ROM 下载模式，从 `0x0` 写入 | 是 |
| `-ota.bin` | 已安装 v0.7.0 或更新版本后的日常更新 | 在线更新、设置门户本地 OTA 或串行应用更新 | 否 |

两种文件不能互换。Factory 镜像包含 Bootloader、分区表、初始 OTA 数据和应用；OTA 镜像
只包含应用程序。不要把 `-ota.bin` 写入 `0x0`，也不要在设置门户上传
`-factory.bin`。

v0.18.0 及更新版本的发布目录还包含同版本 `-model.bin`，供旧设备通过 USB 首次安装
离线语音模型。模型不是独立可启动的固件，也不能上传到设置门户；Factory 已经包含同一
模型，在线更新和设置门户 OTA 则继续只使用 `-ota.bin`。

## 版本兼容

- v0.6.0 及更早版本没有双 OTA 分区，必须先用 `-factory.bin` 完整安装；
- v0.7.0—v0.9.0 可以使用原有本地更新入口上传当前正式版 `-ota.bin`，也可通过 USB
  写入，但这些版本本身不能读取在线清单；
- v0.10.0 起可使用在线更新；正式固件默认读取 `stable.json`，主动开启 Beta 更新后读取
  `testing.json`。固件版本名不会绕过设备保存的通道选择。

## 在线更新

![在线更新页效果图](assets/online-update.svg)

在线更新需要已保存的家庭 Wi-Fi 和可用互联网：

1. 短按 `KEY` 进入系统中心，再切换到 `ONLINE UPDATE`；
2. 按住 `KEY` 2 秒检查版本；
3. 显示 `UPDATE AVAILABLE` 后，再按住 `KEY` 2 秒进入安装确认；
4. 核对目标版本并保持供电，在确认页按住 `KEY` 3 秒；
5. 等待连接、下载、校验和自动重启，期间不要断电；
6. 重启后返回 `ONLINE UPDATE` 核对当前版本。

`NORMAL` 保持家庭 Wi-Fi 连接，每次网络校时成功后复用该连接低调检查一次对应通道，但只
更新页面中的检查结果；`SAVING` 不自动联网检查，用户主动检查或安装时才临时连接，并在
未进入重启的操作结束后关闭无线。两种模式都不会自动下载、自动安装、弹出更新页面或打断
首屏。用户主动检查、确认或开始写入前，设备也不会改变当前启动槽。

### 稳定版与测试版

更新通道默认设为“正式版”。普通用户会一直读取 `stable.json`，不会发现仅发布到
`testing.json` 的候选固件。开发者需要在 `SETTINGS` 页开启设置门户，主动选择“测试版
（开发者）”并保存，之后才会加入灰度。切换通道本身不会下载或安装任何内容。

关闭 Beta 后设备会立即改读稳定清单，但不会自动降级已经安装的候选固件；当稳定通道
出现版本号更高的正式版时即可正常更新并回归正式版本。稳定通道会拒绝任何带 `-dev`、
`-beta` 或 `-rc` 标识的目标，服务端误配置也不会把预发布固件推给普通用户。无论使用哪个
通道，下载与安装都必须从 `ONLINE UPDATE` 页面由实体按键确认，固件不会静默升级。

检查、连接和确认阶段可短按 `BOOT` 取消。开始下载并写入 Flash 后，按键不再中断操作。
失败时页面保留简短原因，详细错误写入 USB 日志；当前固件继续运行。

在线更新依次执行以下校验：

- 通过 HTTPS 获取不超过 4 KiB 的版本清单，并使用 ESP-IDF CA 证书包验证服务器；
- 严格检查通道、项目、硬件、语义化版本、最低可更新版本、镜像大小和下载主机；
- 安装前重新获取清单，确认版本、URL、大小和 SHA-256 未改变；
- 只接受下载地址直接返回的 HTTPS `200` 响应，拒绝重定向；随后使用 ESP-IDF HTTP
  Client 与 OTA API 流式写入未运行槽，同时检查 Content-Length、应用项目名、版本、ESP
  镜像完整性和清单中的 SHA-256；
- 全部校验成功后才切换启动目标。新版本首次稳定启动后确认镜像，未确认前异常复位由
  Bootloader 回滚。

在线更新失败不影响 RTC 和离线页面。设置门户中的本地 OTA 始终保留，供无互联网、在线
服务不可用或需要手动恢复时使用。

## 设置门户本地 OTA

![设置门户等待页效果图](assets/settings-portal.svg)

1. 下载目标版本的 `-ota.bin` 并核对 `SHA256SUMS`；
2. 短按 `KEY` 进入系统中心，再切换到 `SETTINGS`；
3. 按住 `KEY` 3 秒，直到屏幕显示设置热点和二维码；
4. 扫码加入屏幕所示热点；未自动打开页面时访问 `http://192.168.4.1`；
5. 在“本地固件更新”中选择同一项目的 `-ota.bin`，确认后开始更新；
6. 保持供电，等待接收、校验和自动重启；
7. 重启后在 `ONLINE UPDATE` 核对版本。

设置门户使用带设备编号的临时热点和每次会话重新生成的 8 位 WPA2 随机密码，一次只
允许一个客户端，最多开放 5 分钟。等待阶段可短按 `BOOT` 取消，开始接收后按键不会中断
Flash 写入。门户还承载时区、温度单位、音量、更新通道、手机校时和清除
Wi-Fi 配置；本地 OTA 本身不依赖这些偏好。五分钟截止后不再接受新请求；截止前已经开始
的短设置事务会在有限清理时间内完整提交或回滚，OTA 上传则在截止时中止且不会切换启动槽。

本地更新不依赖家庭 Wi-Fi 或互联网。设备没有网络配置时，可先在配网页按
`BOOT: OFFLINE` 进入首屏，待配网热点关闭后再从 `SETTINGS` 开启设置门户。

## 从旧分区迁移

从 v0.6.0 或更早版本迁移：

1. 下载并校验新版本的 `-factory.bin`；
2. 按[发布固件安装指南](user-install.md)进入 ROM 下载模式，从 `0x0` 写入；
3. 正常开机并重新完成一次 Wi-Fi 配置。

完整写入会更新分区表并覆盖 NVS。迁移完成后，后续在线更新和设置门户本地 OTA 都不再
要求进入 ROM 下载模式或重新配网。

## 开发者串行应用与模型更新

设备已具有 v0.7.0+ 分区表，但网页不便使用时，可进入 ROM 下载模式后执行：

```bash
./scripts/update-app.sh --port COM5 --confirm
```

使用仓库中的 v0.20.0 正式发布目录时可直接执行：

```bash
./scripts/update-app.sh \
  --port COM5 \
  --firmware dist/v0.20.0/esp32-rlcd-firmware-v0.20.0-ota.bin \
  --model dist/v0.20.0/esp32-rlcd-firmware-v0.20.0-model.bin \
  --confirm
```

同目录同版本的 `-model.bin` 可被自动识别，因此上例的 `--model` 可以省略；显式传入能让
待写文件更直观。脚本验证发布目录 `SHA256SUMS` 中的 OTA 应用和模型，再在一次 esptool
`write-flash` 中分别写入 `0x10000` 和 `0x610000`，最后只清除 8 KiB OTA 选择数据，
不触碰位于 `0x9000` 的 NVS。v0.7.0 及更新版本的旧分区表没有 `model` 条目，但固定模型
区域原本未分配，因此 v0.20.0 可用本流程安装应用与自 v0.18.0 起提供的模型，并保留
Wi-Fi。设备仍运行 v0.6.0 及更早版本、Bootloader 需要变化、首次安装或完整恢复时，
必须改用
`./scripts/flash.sh` 完整安装。

在线更新和设置门户本地 OTA 仍只更新应用，不能为尚未安装模型的旧设备启用离线语音；
模型已经通过本流程或 Factory 安装后，后续兼容的应用 OTA 不会破坏它。

## 故障排查

- **在线检查不可用**：确认设备已保存可用的 2.4 GHz Wi-Fi，网络校时能成功，再重新
  检查；无互联网时改用设置门户本地 OTA；
- **显示清单或镜像无效**：不要绕过校验，继续运行当前固件并等待服务端修正；
- **设置门户启动不可用**：等待在线任务、自动联网或配网热点结束后重试；
- **手机没有自动打开本地页面**：保持连接更新热点，手动访问 `http://192.168.4.1`；
- **本地网页提示固件无效**：确认选择的是同一项目的 `-ota.bin`，不是
  `-factory.bin`；
- **传输中断**：当前启动槽不会改变；重新开启设置门户再试；
- **新版本无法正常启动**：Bootloader 会尝试回滚。仍无法启动时使用 `-factory.bin`
  进入 ROM 下载模式恢复。

## 安全边界

- 在线更新仅接受 `https://mcu.taifua.com/` 下、清单明确指定且校验一致的 OTA 镜像；
- 设置门户只在 `SETTINGS` 页实体按键长按后临时开放，不提供永久监听端口；
- 上传或下载失败、镜像无效以及 SHA-256 不一致都不会切换启动槽；
- 当前 NVS 尚未启用静态加密，能够物理读取 Flash 的攻击者仍可能取得家庭 Wi-Fi 凭据；
- 设置热点密码不会写入日志或仓库。
