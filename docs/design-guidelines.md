# 产品界面与交互设计规范

本文是 ESP32 RLCD Firmware 的产品设计依据，适用于屏幕页面、实体按键、状态提示和
配置入口。实现细节可以演进，但不得在没有更新本文和说明理由的情况下改变这些原则。

## 设计目标

界面风格为**简约、清爽、明亮**：

- 简约：每个页面只回答一个主要问题，不堆放低价值信息；
- 清爽：使用稳定网格、充足留白、简短标题和一致对齐；
- 明亮：在单色全反射屏上使用纯黑背景和清晰白色像素，保持高对比，不使用灰阶、渐变、
  纹理或厚重装饰框；
- 一眼可读：日常信息应在不操作或一次按键内获得，时间始终是首屏最高层级；
- 离线可用：实际 `NORMAL` 在已有凭据时保持家庭 Wi-Fi 连接，但网络仍不是本地时钟、
  传感器、日历与离线语音的启动前提；断线重试不得长期占用或周期性打断日常页面；
- 可预测：同一个按键在同一信息域内保持相同语义，长按动作只在屏幕明确提示时有效；
- 目标导向：页脚写出按键将到达的页面或完成的动作，不用 `PAGE`、裸 `NEXT`、
  `SYSTEM`、`PORTAL` 等结构或实现术语代替用户目标；
- 安全：清除配置、重启等有副作用的操作必须与普通浏览分离，并提供持续长按或二次确认。

全反射屏适合持续展示而不是频繁动画。页面切换直接、稳定即可，不为装饰目的加入动画；
静态页面只在内容变化、用户操作或必要超时时刷新。

## 信息架构

正常运行页面分为两个互不混杂的一级信息域；异常启动另用独立恢复域：

```text
日常功能域（BOOT）
  主界面 [<-> 天气（已启用时）] <-> 日历
    [<-> 图片（存在有效文件时）] [<-> 音乐（存在有效歌曲时）]

系统中心（KEY）
  对话 -> 设置 -> 在线更新 -> 状态 -> 循环

高优先级临时模态
  闹钟（到点时出现，结束后恢复原页面）

启动恢复域（异常启动或开机按住 KEY）
  在线更新 <-> 设置
```

### 日常功能域

v0.27.0 候选增加本地音乐，具体范围和验收见 [microSD 音乐播放](music-player.md)。
音乐放在 `rlcd/music/`，无卡、无有效歌曲时隐藏音乐页；不自动播放，不自动联网。
音乐页短按 `KEY` 播放/暂停，按住 2 秒下一首；短按 `BOOT` 回到时钟并继续后台播放，
按住 2 秒直接调整音量，保存或取消后仍回音乐页。播放按文件名顺序，末首结束停止。
暂停保留位置；闹钟、对话或维护中断则停止并释放音频和 SD，结束后不自动恢复。
普通设置门户常用项直接呈现，天气与 AI 配置按需展开，各表单保存不覆盖其他未保存输入。
门户 footer 使用低调的 `© 当前年 ESP32 固件` 站点链接，新页面打开，无外部资源依赖。

- **主界面**：RTC 时间、日期、农历、星期、温湿度、三态环境舒适度线稿脸、电池和当前
  Wi-Fi 连接图标；RTC 无效时用稳定占位符保留同一布局；
- **天气**：顶栏显示城市与 RTC 当前日期、星期；中间显示室外天气和三日预报；数据来源、
  获取月日与时间单独放在底部操作提示上方。当前日期不得借用天气缓存日期，RTC 无效时用
  占位符，长城市名不得覆盖日期，也不为日期显示增加每秒重绘。天气开启后即进入 `BOOT`
  页面环，保存配置后打开该页一次。请求中、无数据和失败
  都在同一稳定布局内表达，不使用临时全屏状态页或 3 秒自动返回；同地点已有缓存时，
  断网或后台刷新失败继续显示缓存并明确标记过期状态。天气页按住 `KEY` 2 秒可主动刷新，
  包括在 `SAVING` 下为本次请求临时联网；天气温度不得替换主界面的本地温湿度传感器
  读数；
- **日历**：当前月份、今天、当天农历、星期和时间；
- **图片**：microSD 中经完整校验并成功解码的本地黑白图像。只有至少一张
  有效图片时才进入 `BOOT` 页面环；无卡、挂载失败或没有有效图片时整页隐藏；
- 图片页只表达一个当前画面；存在多张图片时，短按 `KEY` 单向切换下一张并持久保存
  当前选择，按住 `KEY` 2 秒可进入当前图片的单张删除确认；不自动轮播，不把每个文件
  扩展成新页面，也不显示路径、文件名、卡容量或诊断信息；
- 后续新增天气、日程或提醒时，只有适合日常快速查看的内容才能进入此页面环；
- 固件版本、构建信息、传感器诊断、网络错误码和维护说明不得进入日常页面。

### 系统中心

- **状态**：RTC 与备用电源、温湿度传感器、电池、最近时间同步结果，以及当前 Wi-Fi
  链路；历史同步和实时连接必须拆开表达；
- **对话**：由用户主动发起短时会话，不增加新的系统页；满足配置、电源与联网条件时使用
  可选 AI 对话 Beta，离线或省电时回退本地 MultiNet 固定指令。ES7210 双麦克风和离线模型不可用
  时明确降级，原 ES8311/ES7210 回环测试保留为维护诊断；
- **设置**：实际电源状态与原因、时区、温标、播放音量和单个离线闹钟的当前值；
  手动提前省电保留直接长按开关，音量与闹钟开关放在短小的设备端快捷菜单中。
  设置门户保留 RTC、Wi-Fi、本地 OTA 和复杂配置；
- **在线更新**：当前版本、当前通道的最新版本、最近检查结果，以及需要明确确认的 HTTPS
  OTA；测试通道必须有清晰标识；
- 同一字段只保留在最合适的页面。例如固件版本属于在线更新页，不在“状态”页重复。

“状态”页保持五行：`RTC` 合并当前可用性和备用电源结果，`SENSOR`、`BATTERY` 分别
显示本地硬件状态，`TIME SYNC` 显示最近同步结果或时间，`WI-FI` 只显示当前链路。
`SENSOR` 在瞬时读取失败但最近有效温湿度尚未满 180 秒时保留数值并标记 `STALE`，过期后
才显示读取错误。首屏已经持续显示日期与时间，因此状态页不重复当前时刻。

### 设置分工

设备端只做简单、常用的设置，例如开关和少量固定档位。文字输入、多字段编辑、时刻与
重复规则等复杂配置交给设置门户，不在设备上增加多级菜单或逐位输入流程。

设置门户承载时区等多字段偏好、开发者更新通道、手机校时、已保存 Wi-Fi 查看与更换、
本地 OTA、可选的 microSD 图片管理、天气，以及 AI 对话 Beta 的开关、API Key、受控模型
选择和可选官方 API Host。天气配置按“省份 → 城市”的顺序，二者从固件内置的
中国大陆行政区目录级联选择；门户在本地热点下即可完成选择，不依赖
互联网动态加载目录。用户另行填写自己的 QWeather API Host 与 API Key；保存后关闭门户，
设备直连 QWeather 解析地点并获取天气，不经过项目服务器，也不重启整机；天气页在保存后
打开一次，并在固定布局内显示请求状态或结果。API Key 不得回传、预填或写入日志，空白
保存表示保留原值，清除使用独立确认。
设备端直接提供手动提前省电、播放音量与闹钟开关；手动省电
不在设置门户重复提供。时区、温标、闹钟时刻与重复日期等多字段设置仍在门户中完成，
门户音量与闹钟开关复用相同配置，不建立第二套状态。更新通道
默认稳定，加入测试通道必须由用户显式选择并提示候选固件可能不稳定。设置门户由“设置”页
临时开启，作为不进入 `KEY` 页面环的维护入口。设备屏幕提供少量高频设置、操作反馈和安全确认，
不尝试用两个实体按键输入 SSID、密码或大量选项。

### 页面停留与快捷设置

- 切到哪一页就停在哪一页。时钟、天气、日历、图片和系统页都不因无操作自动返回；
  不提供“常驻页”或“默认显示”设置，不把浏览动作另存为偏好。常显信息面板上的
  长时间浏览是正常使用，不应被当作离开页面的理由；
- 正常开机仍进入时钟，不记忆上次页面；天气、图片在后台变为可用时只加入页面环，
  不抢走当前页面。当前天气被关闭或图片已不可用时才回退时钟；天气请求失败仍留在天气
  布局内。图片继续记住选中的文件，不自动轮播；
- `BOOT: HOME` 和语音“主界面”仍明确表示时钟。天气、日历与图片之后按可用状态加入音乐，
  恢复模式继续只开放恢复页；
- 正常“设置”页按住 `KEY` 2 秒进入 `QUICK SETTINGS`，松开后操作。菜单只有音量、
  闹钟开关、网页设置三项：短按 `KEY` 选择下一项，按住 `KEY` 2 秒进入编辑
  或开启网页设置，短按 `BOOT` 返回“设置”页；
- 编辑时短按 `KEY` 循环修改候选值，按住 2 秒保存，短按 `BOOT` 取消本项编辑。音量
  按 10% 档位循环，保留门户设置的原始值直到用户修改；闹钟在列表中长按即切换并保存开关，不增加编辑步骤，同时显示已保存的
  时间与重复规则。未设置 RTC 时提示先校时，不声称闹钟已经可触发；
- 快捷菜单列表不超时；编辑中无操作 30 秒只丢弃草稿并回到该菜单，不返回时钟。闹钟
  抢占或维护模态出现时关闭菜单并丢弃未保存草稿；开启菜单、进入编辑、保存和打开网页均吞掉原长按
  的松开，不得连触发其他动作。菜单长按仍在 1 秒后显示动作和剩余秒数；
- 只有明确保存才写 NVS，每次只修改最新记录中的一个字段；不覆盖其他已保存字段，相同值
  不重复写入。成功后热应用，不重启、不主动开启网络；运行态暂未应用时显示
  `SAVED | APPLYING` 并后台重试，写入失败保留草稿并允许重试或取消。

设置门户开启时家庭 STA 暂停，因此网页必须明确显示“已保存网络”，不得把它
误写为当前连接。门户可直接验证用户输入的新网络，但密码不得回传、预填或记录；候选凭据
只在易失内存中保留，取得 IPv4 后才替换 NVS 中的旧凭据。验证失败时保留旧配置和门户，
成功时关闭门户并按实际电源状态恢复网络，不重启整机：`NORMAL` 重新连接并保持在线，
`SAVING` 完成本次主动校时后关闭无线。“清除 Wi-Fi”作为忘记已保存网络的独立危险操作，
不是更换网络的必经步骤。

### 启动恢复模式

启动恢复是独立的异常维护路径，不进入日常功能域或普通系统中心：

- 同一应用镜像在完成健康判定前连续发生 3 次异常复位后，下一次启动自动进入；开机时按住
  `KEY` 也可主动进入。计划内固件升级重启、正常断电、棕断、USB/JTAG 复位和应用镜像
  变化不沿用旧故障计数；
- 异常计数、上次启动阶段、复位原因、内部堆和主任务栈余量只保存在 RTC 保留内存并写入
  非敏感诊断日志，不形成跨断电的永久故障锁。关闭电源后不按 `KEY` 正常开机即可重新尝试
  完整功能；
- 恢复模式只保留“在线更新”和“设置”两个页面。短按 `KEY` 在两页间切换，短按或长按
  `BOOT` 不返回日常页面，也不自动退出；
- “在线更新”沿用检查、复核与安装确认；“设置”页按住 `KEY` 3 秒开启精简恢复门户。门户
  只提供已保存 Wi-Fi 的查看、更换、清除和本地 OTA，不开放偏好、天气、对话、图片管理、
  手机校时或恢复默认值；
- 自动恢复时若实体按键初始化不可用，设备直接开放精简门户，避免恢复功能依赖已经失效的
  输入路径；网络尚未就绪或启动失败时等待并重试，不因一次竞争永久失去入口；
- 恢复模式不自动开启普通配网热点，没有保存凭据时仍把网络留给维护操作。恢复门户不采用
  普通设置的 5 分钟截止时间，由用户关闭或完成升级、更换网络等操作后结束；
- 恢复模式不启动天气、音频、microSD、温湿度和闹钟等非恢复服务，也不确认处于待验证
  状态的 OTA 镜像。它只用于取得新固件或修复网络配置，不应扩展为第二套设置中心。

开机时按住 `KEY` 进入的是应用恢复模式；关机后按住 `BOOT` 再按 `PWR` 进入的是芯片 ROM
下载模式。后者不运行应用，屏幕也不能显示恢复页面或烧录进度。

单个离线闹钟也从设置门户配置，不增加常驻页面或首屏图标。闹钟按当前固定 UTC 偏移下的
RTC 本地时间和星期触发；到点后临时覆盖其他页面，`BOOT` 停止，首次响铃时 `KEY` 可延后
5 分钟一次，60 秒后自动停止。延后期间恢复原页面，不补发设备关机或错过目标分钟期间的
提醒；短期 RTC 日期回拨不得重复触发，明显异常的远未来记录也不得长期禁用规则。闹钟
启用不改变实际 `SAVING` 状态的显示刷新和联网策略，但 RTC 检查频率不得低于每秒一次。

### v0.18.0 首版离线语音

v0.18.0 首版只做用户主动发起的短时离线识别，不做唤醒词或常驻监听，也不增加语音
开关、首屏图标或新的系统页面。

- 将原“音频”页收敛为当前“对话”页：空闲页明确显示离线语音指令是否可用和操作提示；按住
  `KEY` 2 秒进入会话，屏幕提示后必须先松开 `KEY` 才开始最长 5 秒的监听。监听期间短按
  `KEY` 可提前结束发音并进入识别，短按 `BOOT` 取消整个会话；准备、识别和结果阶段不把
  按键事件落入普通页面导航；
- 原有扬声器与双麦克风回环测试移出主要实体按键流程，作为开发和维护诊断保留，不能与
  离线识别同时占用音频硬件。离线识别只依赖麦克风，播放音量为 `0%` 或扬声器不可用时
  仍应可用；
- 首版只接受没有持久副作用的页面导航指令：主界面、日历、图片、状态和设置，以及只结束
  当前会话的取消指令；图片不存在时不跳转，未知、低置信度或不在白名单内的结果不执行
  动作。语音不能安装固件、清除 Wi-Fi、开启设置热点、删除图片、改变设置或省电请求，
  也不能停止或延后
  闹钟；
- 整个识别在设备本地完成，不要求 Wi-Fi、互联网或 microSD。进入 `SAVING` 后仍允许用户
  主动发起一次短会话；识别期间可以临时请求最高 CPU 频率，但不得改变页面显示的实际
  电源状态、启动网络或留下未释放的性能锁；
- 启动时在独立低优先级任务中完成一次模型完整性校验和识别引擎预热；该任务只读取本地
  Flash，不打开麦克风、扬声器或网络，也不占用串行化 codec 的音频 worker。这样首次
  会话不再把模型初始化时间放在闹钟铃声之前；预热尚未完成时对话页显示准备中；
- 闹钟是最高优先级。闹钟在准备、监听、识别或结果阶段出现时，固件必须取消当前语音、
  清空待处理结果并释放麦克风，再开始提醒音；闹钟结束后不得执行迟到的旧指令，原先
  按住的按键仍须完整松开后才能恢复普通操作；
- 设置门户、本地或在线 OTA、图库下载以及 microSD 导入、删除写事务与语音会话互斥。
  这些操作已开始时拒绝新会话；语音已开始时不得启动它们，只有闹钟可以抢占；
- 原始 PCM 只允许存在于本次会话的易失内存和 MultiNet 内部状态，不写入 Flash、NVS、
  microSD、日志或网络。结束、取消、失败和闹钟抢占都必须清零临时音频并清理识别状态；
  页面和日志只保留不可还原的状态、指令编号、置信结果、耗时和错误码；
- 语音模型缺失、校验失败、内存不足或麦克风不可用时，“对话”页显示简短的
  `CHAT UNAVAILABLE`，其他页面、RTC、闹钟和更新功能继续启动，不反复弹出错误或自动
  联网下载模型。

### AI 对话 Beta

AI 对话复用既有“对话”页、实体按键和串行化 audio worker，不新增首屏图标、常驻开关、
唤醒词或后台麦克风。使用用户自己的 API Key 直连阿里云百炼 Realtime；默认模型为
`qwen3-omni-flash-realtime`，高级设置只提供已经实现和验证的
`qwen-audio-3.0-realtime-flash`，不显示任意模型输入框。

- 一次语音会话开始时同时满足云端已开启、API Key 已保存、实际状态为 `NORMAL`、家庭 Wi-Fi 当前
  取得 IPv4、麦克风与扬声器可用，才选择云端；云端停用、家庭 Wi-Fi 离线或实际状态为
  `SAVING` 时立即回退 MultiNet，不让云端连接超时阻塞本地体验。后端在整段会话内固定，
  运行中电源状态变化不切换，也不中断已经开始的用户事务；
- 按住 `KEY` 2 秒进入，看到提示后松开再说话；云端输入最长 10 秒，监听时短按 `KEY`
  提前结束，连接、监听、思考和播放阶段短按 `BOOT` 取消。同一 TLS WebSocket
  会话最多保留 5 轮服务端上下文，每轮回复完成后最长等待 30 秒续问；新一轮只在会话
  开始后的 5 分钟内准入，已经开始的收音和回答不因总时限被截断；
- 轮次未满时，播放中短按 `KEY` 先停止当前回复再进入下一轮；回复完成后显示
  `FOLLOW-UP`，短按 `KEY` 继续、短按 `BOOT` 结束。第 5 轮、30 秒续问超时或
  5 分钟准入期限后不再开启新一轮。会话仍为半双工，麦克风与扬声器不同时工作；
- 回答默认使用一至三个适合朗读的短句；内容较多时先给结论和最重要的三点，再由用户
  继续追问。默认 Qwen3 Omni 同时设置受控输出上限，避免一轮回答长期占用设备；
- 流式回答使用 4 行左对齐滚动窗口，按实际字体像素宽度换行；字幕由本地已经播放的 PCM
  进度驱动，新内容覆盖最旧行，不因服务端提前生成完整文字而抢跑到回答末尾；
- 云端回复只在“对话”页展示并由扬声器播放，不进入本地指令白名单，不导航页面，也不
  安装固件、修改设置、控制闹钟或执行其他设备动作。离线 MultiNet 继续只执行既有安全
  导航指令；
- 设置门户提供明确开关和 API Key，并在高级设置中提供固定枚举的模型与可选 API Host。
  关闭只停用云端并保留 Key；空白 Key 保存表示保留，独立清除删除 Key、关闭云端，并
  恢复默认模型与北京共享 Host。API Host 留空使用 `dashscope.aliyuncs.com`；输入时只
  接受北京/新加坡的百炼共享 Host 或单标签 Workspace 专属 Host，不接受 scheme、路径、
  端口、IP、代理、自建转发和其他域名。固件内部固定 Realtime 路径与受控模型参数，不向
  用户提供完整 URL、独立 Workspace ID、App ID 或任意模型 ID 字段；
- 两个可选模型都使用手动 PTT、有界多轮半双工和相同安全边界，不启用 `smart_turn`、
  Function Calling、联网搜索或自动执行动作。模型自身支持某项能力不等于固件已经提供；
- AI 对话通过验证服务器证书的 TLS WebSocket 上传各轮 16 kHz、16-bit 单声道 PCM 和
  必要模型标识，并接收识别文字、回复文字和 24 kHz、16-bit 单声道合成语音。PCM、文字
  和播放缓冲只存在于本次会话的易失内存，不写入 Flash、NVS、microSD 或日志；“不持久化”
  不得误写成“不上传”，页面与用户文档必须在开启前说明数据会发送给第三方且可能产生
  费用；
- API Key 保存在单独的 NVS 配置中，状态接口和网页不得返回或预填 Key，空白保存表示保留，
  清除必须使用独立确认。Authorization 头、Key、请求正文、PCM 和可还原对话内容不得进入
  USB 日志；正式配置将编译期最高日志级别锁定为 `INFO`；
- 当前未启用 Flash Encryption 或 NVS Encryption，不能承诺凭据抵抗物理 Flash 读取。
  用户文档应建议使用专用最小权限 Key、消费保护和定期轮换，并在设备遗失、转让或送修前
  清除配置、吊销旧 Key；
- 云端会话与设置门户、本地/在线 OTA、图库下载、microSD 导入或删除写事务互斥；闹钟仍是
  唯一抢占者。取消、失败、超时、闹钟抢占和迟到的旧代际结果都必须释放网络、codec、I2S、
  性能锁及临时缓冲，不得在结束后执行回复或设备动作。

### 省电规则

自动低电规则始终生效，不是需要用户选择的模式，也不能被普通设置关闭。设备只保存一个
“手动提前省电”布尔偏好，默认关闭；实际运行状态始终只有 `NORMAL` 或 `SAVING`。设置页
显示实际状态及最主要原因：`NORMAL`、`NORMAL | USB`、`SAVING | MANUAL` 或
`SAVING | LOW BAT`，不再显示额外的配置模式。USB 数据主机的优先级最高；没有数据主机
时，手动请求优先于低电原因显示。

保存已完成但运行态暂时无法切换时，设置页持续显示已保存的手动目标和 `PENDING`，后台
继续重试；不得退回旧配置造成下一次按键看似没有生效。

- 冷启动取得首个有效电量时，不高于 20% 进入 `SAVING`，否则进入 `NORMAL`；运行期间，
  `NORMAL` 下连续两次有效采样均不高于 20% 才进入 `SAVING`，低电原因的 `SAVING` 下
  连续两次均不低于 25% 才恢复 `NORMAL`。21%—24% 是滞回区，无效读数保持当前状态并
  取消尚未确认的切换；
- 检测到 USB 数据主机时立即使用 `NORMAL` 并取消尚未确认的低电切换，即使用户此前已
  请求手动省电也一样；不再检测到主机后不复用旧读数，而是重新取得电量样本，再按手动
  请求和自动低电规则决定状态；
- `usb_serial_jtag_is_connected()` 只根据电脑 USB 主机持续发送的 SOF 判断数据连接。
  原板没有把 VBUS 或 ETA6098 充电状态接入 ESP32，因此普通充电器、充电宝和纯充电线
  不能被可靠识别；这类供电仍按 GPIO4 电压估算和阈值规则运行。若估算值连续两次达到
  25%，设备可以按恢复阈值回到 `NORMAL`，但不能把结果显示为已检测到电源；
- GPIO4 读取的是充放电和负载下的电池端电压，换算百分比不是电量计给出的真实荷电状态。
  插线后电压抬升可能让百分比立即上升，拔线后也可能立即回落；不得把这类变化解释为电池
  瞬间充入相应容量，也不得据此绘制可靠的充电或外部供电标识。确认电脑 USB 数据主机时，
  首屏以 `USB` 替代电池百分比，“状态”页只显示 `USB` 和端电压；普通充电器无法触发这项
  保护性表达；
- “设置”页按住 `BOOT` 2 秒只切换“手动提前省电”的开与关，保存后立即尝试热应用，
  不开启设置热点。开启时在没有 USB 数据主机的情况下进入 `SAVING`；关闭只撤销手动请求，
  不代表强制 `NORMAL`，电量仍不高于低电阈值时继续显示 `SAVING | LOW BAT`；
- 实际 `NORMAL` 显示等大的 `HH:MM:SS`，按秒刷新首屏；温湿度约 5 秒采样一次，电池约
  30 秒采样一次。有已保存凭据时保持家庭 STA 与 IPv4 连接，使用 ESP-IDF
  `WIFI_PS_MIN_MODEM` 降低关联空闲功耗，自动校时和更新检查复用现有连接；断线后按
  1、5、15 分钟退避，之后每 15 分钟重试；
- 实际 `SAVING` 显示 `HH:MM`，只在分钟变化时刷新首屏；温湿度约 60 秒采样一次，不执行
  自动校时、自动重试或自动更新检查，也不保持家庭 Wi-Fi 连接。为及时判断自动低电进入
  与恢复条件，电池约 10 秒采样一次，但电压采样本身不要求刷新静态页面；手动校时、在线
  更新和图库下载只在操作期间临时联网，结束后关闭无线；
- CPU 在 `NORMAL` 保持 240 MHz，在 `SAVING` 允许 ESP-IDF DFS 按工作负载在 80—240 MHz
  间调节；当前版本不使用 Light-sleep 或 Deep-sleep，全反射屏继续常显；
- 两种实际状态都保留手动校时、在线检查与 OTA、设置门户和本地 OTA。没有已保存 Wi-Fi 凭据的
  首次配网是例外，即使实际处于 `SAVING` 也会按正常流程开放临时热点；
- 手动请求和实际状态切换不重启、不切页，也不中断已经开始的手动联网、OTA、闹钟、音频或
  存储操作；进入 `SAVING` 时等待已有网络事务结束后关闭 Wi-Fi，恢复 `NORMAL` 时自动
  连接并保持家庭网络。

省电状态只表示减少显示刷新、传感器采样、CPU 占用并停止常驻联网，不承诺固定续航时长
或提升倍数。

## 实体按键

文档和屏幕使用板上丝印 `BOOT`、`KEY`、`PWR`，不使用可能随摆放方向变化的“左键”或
“右键”。

| 按键 | 短按 | 长按 |
| --- | --- | --- |
| `BOOT` | 日常页面中切换下一页；系统中心中返回主界面 | “设置”页按住 2 秒切换手动提前省电；音乐页按住 2 秒调音量 |
| `KEY` | 主界面、天气和日历中进入对话页；多图图片页中切换下一张；音乐页播放/暂停；系统中心中切换下一系统页 | 天气页刷新；图片页进入单张删除确认；系统页执行当前页面明确提示的操作 |
| `PWR` | 正常开机 | 物理关机 |

关机后按住 `BOOT` 再按 `PWR` 仍用于选择 ESP32-S3 ROM 下载模式。这是硬件启动行为，
不属于运行时页面交互。

应用能够启动时，也可在开机期间按住 `KEY` 进入恢复模式。恢复模式中短按 `KEY` 只在
“在线更新”和“设置”间切换；`BOOT` 不进入普通页面环，恢复完成后按屏幕提示关机再正常
开机。

正常运行的上下文长按只执行以下明确操作：

- 天气页按住 `KEY` 2 秒：立即刷新天气；
- 图片页按住 `KEY` 2 秒：进入当前图片的单张删除确认，不直接写卡；
- “状态”页按住 `KEY` 2 秒：立即执行一次 SNTP 校时；
- “对话”页按住 `KEY` 2 秒：提示松开按键，松开后开始一次语音会话；本地指令最长 5 秒，
  云端 Beta 最长 10 秒；原回环测试移到开发和维护诊断入口；
- “设置”页按住 `BOOT` 2 秒：切换并保存手动提前省电，随后原地应用，不开启设置
  门户；
- 正常“设置”页按住 `KEY` 2 秒：进入设备快捷设置；网页设置作为其中一个明确入口，
  仍采用有时限、随机密码保护的本地热点。恢复模式保留原有直接打开精简门户的操作；
- “在线更新”页按住 `KEY` 2 秒：检查新版本；已有可用版本时进入安装确认，确认页再次按住
  `KEY` 3 秒才开始下载和写入；
- 音乐页按住 `KEY` 2 秒下一首，按住 `BOOT` 2 秒直接调音量；
- 未明确提供长按动作的其他上下文，均不执行动作，松开
  也不得误判为短按。

上述有效长按统一在持续 1 秒后显示动作名称、剩余秒数和 `RELEASE TO CANCEL`。
未达到 2 秒或 3 秒动作阈值前松开只取消长按，不得再执行该按键的短按动作；动作触发后
产生的松开同样不得落入普通导航。双键同时按下、闹钟或其他模态占用输入时不显示长按提示。

图片删除确认必须与发起长按分成两次独立输入。普通短按仍执行切图或进入系统中心；持续按住
1 秒出现统一长按提示后，满 2 秒进入确认页。进入确认页后必须
先完整松开 `KEY`，短按 `KEY` 才删除，短按 `BOOT` 取消，10 秒无操作也自动取消。确认页
始终显示待删除的当前图片和明确按键提示，不提供批量删除。确认后由异步任务执行写卡，
执行期间暂停普通页面导航并显示正在删除状态；成功后显示下一张，删除末张后回到首张，
删除最后一张图片后隐藏图片页，失败则保留文件、当前图片和运行时目录。

普通页面和快捷菜单列表没有无操作超时。草稿编辑、图片删除确认、设置热点、语音会话
和在线安装确认仍使用各自必要的时限；取消或结束后恢复所在功能页，不跳回时钟。
语音监听时短按
`BOOT` 取消会话并清除临时音频；AI 思考和播放阶段也由 `BOOT` 取消，播放中
短按 `KEY` 可跳过剩余回复进入下一轮。`FOLLOW-UP` 中短按 `KEY` 续问，短按 `BOOT`
正常结束。在线检查、连接和
确认阶段可用 `BOOT` 取消；开始写入固件后按键不得中断。设置门户等待连接或普通配置时
可用 `BOOT` 关闭；开始接收本地
固件后不得中断写入。这些临时覆盖只在屏幕明确提示时生效，退出操作状态后恢复表格中的
页面导航语义。

闹钟是最高优先级的运行时模态：出现时先安全结束临时音频诊断、离线语音或 AI 对话会话，
并丢弃尚未应用的识别结果；两个按键只执行屏幕所示的停止或延后操作，不得落入页面切换、
设置或更新动作。模态出现前已经按住的按键必须等到完整松开后才能重新生效，避免原长按
被误判。闹钟结束后恢复此前页面及普通按键语义，但不恢复已经取消的语音会话。

设置门户使用标准 Wi-Fi 二维码，并同时显示临时热点 SSID、随机密码和
`192.168.4.1`。网页另行显示已保存的家庭 Wi-Fi 名称，且不得显示密码。清除 Wi-Fi
必须在网页中单独确认，只清除网络凭据，不清除其他偏好；本地 OTA 必须使用 OTA 镜像，并在
开始接收前再次确认。手机校时由用户主动执行，成功写入并回读 RTC 后才显示完成。

首次配网页明确显示 `BOOT: OFFLINE`，允许用户立即跳过二维码回到首屏；该操作不清除
配置、不关闭尚未到期的本地配网热点，也不改变正常页面中的 `BOOT` 语义。

microSD 是完全可选的本地内容源：无卡不显示启动错误，不影响时钟、日历、
传感器、音频或更新功能；日常展示只读访问存储卡。只有用户在设置门户明确发起的图片
导入，或在设备图片页、设置门户明确确认的单张删除，才可以临时以写方式挂载卡。导入
必须有大小上限、临时文件、完整格式校验和内容摘要，有服务端预期摘要时必须比对，失败时
清理临时文件；删除只接受当前运行时目录中已校验图片的精确标识，并经过对应入口的明确
确认；文件尚未成功移除时不得改变当前目录，文件已成功移除后运行时目录必须同步反映
磁盘结果，卸载阶段的附加错误保留到日志。
固件不自动格式化、覆盖、改名、清理或批量删除已有文件，也不在卡上保存设置、日志、
温湿度历史或音频诊断数据。受控导入和删除完成后立即安全更新运行时缓存；这不代表支持
运行中插卡、拔卡或换卡，物理介质变化仍只在下次开机扫描。

手机导入的 JPEG/PNG 原图必须只在当前浏览器中解码、缩放、二值化和预览；
设备只接收最终的 400 × 300 PBM，原图不上传到设备或服务器。公共演示图下载也
必须由用户主动确认，只在设备已保存可用 Wi-Fi 时进行，不在启动或普通运行时
自动下载。无卡时设置门户应将相关入口显示为不可用，但不用错误弹层打扰其他设置。

## 视觉系统

- 固定画布：400 × 300，黑底白字；
- 页面左右安全边距：至少 12 像素；
- 图片页的文件画布仍为 400 × 300 纯黑白像素，但底部 50 像素是固件保留的操作区；
  主要图像内容应放在 `y=0`—`249`，固件在黑色底上重画分隔线和 footer；
- 系统页使用统一的标题、顶部细分隔线、内容网格、底部细分隔线和操作提示；
- 页面标题简短明确，不使用项目名代替页面用途；系统页显示 `1/4`—`4/4` 位置提示；
- 大标题使用约 24 像素字体，主要数据使用 14—20 像素字体，底部操作提示使用 12—13
  像素字体；同层级字号、行距和左右起点保持一致；
- 首屏环境舒适度使用无外框的同尺寸黑白线稿脸，只改变嘴形表达舒适、一般和需调整；
  不依赖 Unicode Emoji，不增加文字标签、颜色或动画；首个有效温湿度样本立即给出对应
  表情，瞬时读取失败沿用最近有效结果，数据超过 180 秒未更新后才隐藏；
- 每页优先控制在 3—5 个信息组；状态使用简短的 `OK`、`NOT READY`、`NOT CONFIGURED`
  等词，不直接铺陈错误码；
- 二维码必须采用标准白底黑码、完整静区和整数像素倍率，旁边保留可理解的文字说明；
- 普通页面避免整屏外框、连续粗线、阴影和纯装饰图标。状态模态页可以使用单个细框强化
  当前操作，但不能与日常页面竞争视觉层级；
- 闹钟模态不显示系统页位置，使用大号当前时间、一个短状态和
  `BOOT: STOP | KEY: SNOOZE 5m`；延后后第二次响铃只显示 `BOOT: STOP`，不加入动画；
- 页面底部提示保持简短并直接命名目的地：月历在有图时使用
  `BOOT: IMAGE | KEY: CHAT`，无图时使用 `BOOT: HOME | KEY: CHAT`；图片页多图时使用
  `BOOT: HOME | KEY: NEXT IMAGE | 2/6`，单图时使用 `BOOT: HOME | KEY: CHAT`，
  有可用音乐时，上述末个日常页的 `BOOT: HOME` 改为 `BOOT: MUSIC`。
  图片页另行明确 `HOLD KEY 2s: DELETE IMAGE`；删除确认页在原长按尚未松开时使用
  `RELEASE KEY | BOOT: CANCEL`，松开后改为 `BOOT: CANCEL | KEY: DELETE`；系统页使用
  明确的环形目的地：状态到 `CHAT`、对话到 `SETTINGS`、设置到 `ONLINE UPDATE`、
  在线更新到 `STATUS`，同时都保留 `BOOT: HOME`；“设置”页第二行根据当前请求显示下一动作
  `HOLD BOOT 2s: MANUAL SAVING ON/OFF`，并用 `HOLD KEY 2s: QUICK SETTINGS` 表达快捷设置
  目标，其他系统页有长按动作时只追加当前页面的那一个动作；状态页使用 `SYNC TIME`，
  在线更新页按状态使用 `CHECK UPDATE` 或 `REVIEW UPDATE`。“对话”空闲页在内容区按模式
  分别显示 `Hold KEY 2s to ask` 或 `Hold KEY 2s for a command`，footer 使用
  `BOOT: HOME | KEY: SETTINGS`；监听页使用
  `KEY: DONE | BOOT: CANCEL`，AI 连接与思考页只保留 `BOOT: CANCEL`；播放页在轮次未满时
  显示 `KEY: NEXT TURN | BOOT: CANCEL`，第 5 轮只显示 `BOOT: CANCEL`；续问页显示
  `KEY: CONTINUE | BOOT: END`；
- “未听到”“未识别”“不可用”“取消”“失败”和会话轮次结束等短暂结果态，在输入门控尚未
  恢复时只显示 `RETURNING TO CHAT...`；不得提前显示尚不可执行的重试或页面导航动作；

“明亮”表示清晰、高对比和有呼吸感，不表示用白色大面积填满屏幕。反色块只用于今天、
当前选择或需要用户确认的焦点。

## 状态与反馈

- 用户主动发起的异步操作显示正在做什么，例如启动 Wi-Fi、连接网络、等待 NTP、写入
  RTC；首屏 Wi-Fi 图标只表达当前 STA 已取得 IPv4，未连接和关闭无线时留空。取得 IPv4
  但 NTP 或互联网不可用时仍显示图标；“状态”页用 `TIME SYNC` 承载最近同步结果，另用
  `WI-FI` 表达 `CONNECTED`、`CONNECTING`、`OFFLINE | RETRY`、`OFFLINE`、
  `OFF | SAVING`、`NOT CONFIGURED` 或 `NOT READY`。后台连接和重试不覆盖日常页面；
- 天气主动获取的进行中和失败状态必须留在天气页固定布局内；保存配置后只打开该页一次，
  天气页 2 秒长按也只在该页显示进度与结果，不显示临时全屏天气状态，也不按 3 秒结果计时
  自动返回。后台刷新失败且存在同地点缓存时继续显示缓存，详细错误码只写入 USB 日志；
- 温湿度首次取得有效样本时立即显示数值和三态表情；一次读取失败先由驱动执行一次恢复
  重试，仍失败时首屏保留最近有效结果，状态页标记 `STALE`。只有最近有效样本满 180 秒
  未更新，首屏才使用占位符并隐藏表情，状态页改为读取错误；后续成功采样立即恢复正常
  表达；
- microSD 缺失、文件系统不可读或没有有效图片时，不在启动时显示全屏错误，而是隐藏
  图片页并保留原日常页面环；具体原因保留在 USB 日志和电脑端检查工具中；
- 图片导入、删除和公共演示图下载由用户主动发起，必须显示正在写入、校验、完成或
  失败；设备端删除确认后异步执行，完成后直接更新运行时图片缓存，失败时保持已有缓存
  和其他本地功能可用；删除后显示下一张，删除末张后回到首张，删除最后一张图片后图片页
  自然隐藏；
- 普通设置、恢复偏好、图片导入、更换或清除 Wi-Fi 不得用整机重启代替运行时状态管理；
  Wi-Fi 验证、清除凭据或在线图库切换网络时可以关闭相应热点，但 RTC、屏幕和本地任务
  继续运行。
  只有固件 OTA 为进入新应用分区自动重启；
- 成功或失败的临时操作结果至少保持 2 秒，再回到发起页面；天气获取状态不是临时结果页，
  始终在天气布局内表达。删除后显示下一张，删除末张后回到首张，删除最后一张图片后回到
  首屏；
- 错误信息说明用户下一步能做什么，详细错误码保留在 USB 日志；
- 无法直接测量的硬件状态必须标明证据边界。RTC 备用电池只能在真实断电后的下一次开机
  根据停振标志和跨启动时间标记显示 `UNTESTED`、`VERIFIED` 或 `FAILED`，不得把 RTC
  当前可读或主电池电量误写成备用电池正常；
- 开发和维护用的音频回环测试只能确认扬声器数据已成功写入，`TONE PLAYED` 或
  `VOICE PLAYED` 不等于用户一定听到声音。原始语音最多 5 秒且只存在 PSRAM，不写入
  Flash、NVS、microSD、日志或网络；播放、取消或失败后立即覆写并释放。诊断状态只保留
  时长、两路去直流强度与流程结果，不保留可还原的音频；
- v0.18.0 离线语音只在用户完成 2 秒长按后短时采集。空闲、页面浏览、联网和待机期间
  麦克风不得持续送入识别器；屏幕必须区分准备、监听、识别、已识别、未识别、已取消、
  不可用和失败。识别结果只有在当前会话仍有效、没有闹钟或维护事务抢占且属于安全白名单
  时才能应用一次；
- AI 对话必须区分连接、等待松开、监听、思考、播放、切换下一轮、续问、完成、
  取消和失败，
  并以 `TURN x/5` 表达当前轮次；转写与回复的累计更新应限频刷新，避免为每个文本片段
  刷新全反射屏并干扰音频。回复字幕跟随本地播放进度，而不是直接跟随服务端生成进度；
  AI 回复只展示和播放，
  任何内容都不得进入设备命令策略；
- 设置门户中的更换 Wi-Fi、清除 Wi-Fi、恢复默认值和本地 OTA 相互独立；取消或失败不得
  顺带修改其他数据，所有有副作用的操作都必须有明确确认和结果反馈；
- 在线更新可以在一次成功联网后低调检查，但不得弹出页面、自动安装或打断日常功能；安装
  必须经过“在线更新”页的实体按键确认。检查结果使用 `NOT CHECKED`、`CHECKING`、
  `UP TO DATE`、`UPDATE AVAILABLE` 或 `FAILED` 等短状态；确认、下载、校验和结果使用独立
  状态模态，下载中显示实际百分比；普通用户默认只读稳定通道，测试通道不通过静默开关或
  公共下载入口向所有设备开放；
- 在线与本地固件升级都只写入非活动 OTA 分区，镜像校验成功后才切换启动分区，失败时
  保留当前可启动固件。本地 OTA 由设置门户提供，始终作为无互联网时的维护与恢复入口；
- 待验证 OTA 只能在普通模式确认显示和按键可用、完成首轮周期任务、成功显示页面并运行
  至少 15 秒后确认；调用失败时按 5 秒间隔重试。普通模式在相同里程碑成立且稳定运行满
  60 秒后才清除本镜像的连续异常复位计数；恢复模式不得确认待验证镜像；
- 连续异常启动或开机按住 `KEY` 时使用独立恢复页面与精简门户。恢复入口不得依赖天气、
  音频、microSD、温湿度或闹钟初始化成功，也不得在恢复网页重新开放与修复无关的表单；
- 页面切换、长按动作和超时规则必须由纯逻辑主机测试覆盖，实机再验证按键电平、刷新效果
  和网络联动。
- RTC 备用电池只维持走时，不能给 ESP32、屏幕或扬声器供电；使用 `PWR` 物理关机后闹钟
  不会响，也不会在下次开机补发。当前硬件与固件不提供关机唤醒闹钟。

## 设计检查清单

新增或修改页面前确认：

1. 该信息属于日常功能域还是系统中心，是否与其他页面重复；
2. 页面能否用一句话说明主要目的；
3. 不看文档时，底部提示能否说明当前可用按键；
4. 长按是否只在相关页面生效，危险操作是否有足够确认；
5. 字号、留白、分隔线、位置提示和返回行为是否与同类页面一致；
6. 是否避免了无意义刷新、动画和调试信息；设备设置是否限于简单开关与少量档位，
   复杂配置是否留在设置门户；
7. 主机测试、SVG 效果图、用户文档和实机验收记录是否同步更新。
8. 断网、无互联网或 NTP 不可用时，是否仍能稳定使用所有不依赖网络的本地功能；
9. 功能在无 microSD 时是否自然收缩，且任何写卡操作是否仅由用户明确确认后发生。
10. 音频功能是否只在明确提示和用户主动输入后采集，原始音频是否只在易失内存暂存，
    模型缺失、闹钟抢占和异步结果迟到时是否安全降级；云端模式是否明确告知上传边界。
11. 云端凭据是否不回传、不预填、不记录，API Host 是否只接受官方白名单，未加密 NVS
    的物理读取风险、第三方数据处理与可能计费是否在用户配置前清楚说明。
12. 启动关键路径是否会在同一镜像连续异常后进入最小恢复模式；恢复页、精简门户、OTA
    延迟确认和正常断电不误触发是否分别经过纯逻辑测试与目标板验证。

## 参考原则

- [Apple：Status bars](https://developer.apple.com/design/human-interface-guidelines/status-bars)：
  状态栏图标表达设备当前状态，Wi-Fi 图标用于判断当前是否存在 Wi-Fi 连接；
- [Apple：Designing for watchOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos/)：强调一眼可读、短交互和浅层导航；
- [Apple：Settings](https://developer.apple.com/design/human-interface-guidelines/settings)：低频设置独立收纳，避免设置过多导致难以理解；
- [Garmin：Designing Workflows and Interactions](https://developer.garmin.com/connect-iq/user-experience-guidelines/designing-workflows-and-interactions/)：实体按键抽象行为、页面环、设置菜单、确认和最少交互；
- [Garmin：Views](https://developer.garmin.com/connect-iq/user-experience-guidelines/views/)：用页面层级和页面环表达信息关系；
- [Espressif：Voice Chat Example](https://github.com/espressif/esp-agents-firmware/blob/main/examples/voice_chat/README.md)
  将自然对话称为 Voice Chat；[ESP-SR MultiNet](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/speech_command_recognition/README.html)
  则明确描述为命令词识别。当前页面因此按用途命名为 `CHAT`，模式分别使用 `AI CHAT` 和
  `OFFLINE COMMANDS`，不把输入媒介 `VOICE` 当作页面目的；
- [微雪 ESP32-S3-RLCD-4.2 文档](https://docs.waveshare.net/ESP32-S3-RLCD-4.2/)：硬件按键、显示和电源行为依据。
