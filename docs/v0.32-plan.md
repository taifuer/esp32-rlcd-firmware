# v0.32.0 对话与日常操作优化

2026-09-29 确认实施，用户随后同意将 `0.32.0-dev.3` 发布为正式 `0.32.0`。
主机检查、用户反馈与专项实机验收分开记录，不用构建成功代替设备测试。

## 范围

- 网页“常用 → 显示页面”同时管理显隐和顺序。时钟固定第一位，六个功能页使用上移、
  下移按钮调整；隐藏或不可用时跳过，但不丢失排序位置。保存不重启、不切走仍可用的
  当前页，设备页脚与 BOOT 实际顺序一致。系统中心和启动恢复顺序不变。
- AI 增加五个官方音色与“日常简洁 / 英语练习”两种回答风格。默认保留原有音色和
  简洁回答，不更换服务商或模型；复杂配置仍在门户，保存不自动测试付费接口。
- AI 失败后保留提示，清理完成且按键松开后，可短按 KEY 重新发起、BOOT 返回。
  重试是新的会话，需要重新说话，不自动重连、不重复发送录音；省电下仅提供返回。
- 音乐批量上传在当前网页保留队列，显示完成、失败、待上传数量，提供明确的重试与
  继续操作。断线导致的未知结果先核对，不直接重新上传；刷新或关闭网页后不承诺保留文件。

不增加设备菜单、唤醒词、后台监听、新功耗策略或分区，不改首屏布局。API Key、Wi-Fi、
天气、闹钟、音乐模式及其他现有设置应保留；设置格式升级写入另一槽，保留旧记录。

- [x] 门户独立表单草稿、排序按钮边界、保存失败、队列失败与未知上传结果恢复。

页面环覆盖 720 种顺序 × 64 种显隐 × 16 种功能可用组合，共 737,280 个组合。
真实渲染接线额外检查 Chat 移到中间时的动态页脚。AI 重试采用纯状态测试、应用接线
检查与独立代码审查；字体测试解码实际 U8g2 字库确认提示和页脚不越界。

设置 schema v11 使用新的 `cfg11_a/b`，旧显隐、音乐方式等保持不变；AI schema 3
补全默认音色与风格，在另一槽提交并保留源记录。回退旧版不能编辑新的偏好，避免在
不同版本间反复修改；AI 旧版也不能识别新格式，测试失败时优先通过后续 OTA 修复。

## 用户优先验收

1. OTA 后原有设置保留，首屏正常。在“常用 → 显示页面”把对话移到前面、保存并关闭
   门户，确认 BOOT 和页脚按新顺序切换；重启后顺序仍在，隐藏页重新显示后位置不变。
2. 同 Wi-Fi 授权门户中选择音色和英语练习，点击“保存对话设置”；关闭门户后主动对话，
   确认声音、简短回答和多轮正常。恢复日常简洁后确认原体验仍可用。
   开关、官方 Host、受控模型及确认清除也可直接操作；首次填写或更换 API Key 才需热点。
3. 若自然遇到连接失败，等待提示出现后短按 KEY 重试或 BOOT 返回。无意制造收费调用、
   不要求用户提供真实 Key。连续会话资源回收仍按长期专项计划验收。
4. 有 microSD 时多选几首歌曲，确认成功保留，失败项可重试、后续文件可继续；不覆盖
   同名文件。无卡时媒体操作不可用，但页面与对话设置仍可保存。

## dev.2：同 Wi-Fi 修改对话偏好

用户确认开放开关、音色和回答风格；API Key、Host 等连接配置仍在设备热点修改。
原页面把整个 AI 表单都设为热点可用，因此已配置凭据的用户在同 Wi-Fi 下仍无法选择。
本次拆为“保存对话偏好”和“服务与凭据”两个独立表单：

- 新增 `/api/conversation/preferences`，仅接受 `enabled`、`voice`、`reply_style` 三项。
  同 Wi-Fi 访问沿用 Host、访问码/token、会话有效期和写入互斥检查。
- 后端在配置锁内合并最新记录，只改三项偏好；拒绝凭据、Host、模型、未知或重复字段。
  凭据表单省略偏好时同样保留最新值，避免两个表单交叉保存互相覆盖。
- 单独保存和重新读取不会清掉另一表单的未提交修改；未保存 Key 不因保存偏好而丢失。
  新设备没有 Key 时明确提示先配置，不假装保存成功。保存不重启、不切换网络、不发起云调用。
- 凭据写入和清除的接口仍不允许同 Wi-Fi 请求；前端禁用只是提示，服务端权限不放宽。
  设置格式仍是 AI schema 3、通用设置 schema 11，不增加迁移或修改分区。

用户已确认 dev.1 在热点下能够操作 AI 选项；dev.2 的同 Wi-Fi 操作和设备对话效果待验收。

## dev.3：天气与 AI 的统一设置方式

用户确认 dev.2 可用，随后要求两项功能统一为“只有 API Key 录入、更换需要热点”。
本次不改设备页面、功耗、模型参数或固件分区：

- 天气设置表单独立保存开关、Host、省份和城市；AI 设置保存开关、音色、风格、模型、Host。
  同 Wi-Fi 的临时授权门户和热点均可操作，只允许既有官方域名与受支持的模型。
- 两个独立 `/key` 接口仍仅热点可用，只接收 `api_key`，不改其他最新配置。
  普通设置接口拒绝携带 Key（包括空值与编码字段），后端锁内合并，不依赖前端禁用控件。
- 两项清除操作开放到同 Wi-Fi，保留精确确认字段、前端确认、Host/token 校验和事务互斥。
  提示会删除本功能配置并清空相应草稿；不顺带改变另一功能。
- 保存一组不覆盖另一组草稿，Key-only 读取也不刷新省市列表。天气列表读取失败时禁止
  保存半加载设置；单独保存或重新读取 Key 不能绕过此门控。网络中断不自动重放请求。
- 天气保存仍只在退出门户后获取最终配置；AI 设置保存不连接云端。两者均不重启、
  不切页、不切换家庭网络。现有天气 schema 1、AI schema 3 和通用设置 schema 11 不变。
- 固定 WebSocket 组件的内部跳转会绕过首次 Host 校验，因此在构建目录生成受控副本，
  遇到 3xx 明确失败，不跟随 Location。上游源摘要和补丁结构不匹配时拒绝构建；不修改
  外部 checkout，不提交第三方源文件，正常握手与证书验证保持原样。
