# v0.30.0 日常体验整理

2026-09-27 完成 dev.1、dev.2 开发与 Beta OTA 后，用户反馈“没什么问题，发布吧”，
授权将同一功能源码发布为 v0.30.0。以下保留候选阶段记录；没有通过 USB 写入设备。

## 本版范围

### 天气保存不打断设置

- 保存天气配置后留在网页，既不重启，也不关闭热点或强制切到天气页。
- 保留其他分区的未保存内容；天气表单独立刷新，API Key 不回显，保存后清空输入框。
- 配置立即保存并更新启用状态；门户期间不发起天气请求。关闭门户后再尝试获取一次，
  使用最后保存的有效配置，多次保存合并；停用或清除取消待获取操作。
- 后续天气结果只更新缓存与状态，不跳页。手动进入天气页、长按刷新及原有周期刷新保留。
- 局域网仍不开放天气凭据编辑；不为保持门户而并发争用维护网络。OTA、Wi-Fi 更换与图库
  等操作拥有既有优先级，取消和失败不得遗留网络所有权。这些独立维护事务会取消本次
  延后获取，之后由正常模式周期刷新或用户在天气页手动刷新；不跨会话遗留待执行操作。

### 日常页面显隐

- 网页“常用”提供可折叠的“显示页面”，独立保存天气、市场、月历、图片、音乐、对话六项。
  默认全部勾选，升级后维持原行为；六项都关闭时只留下时钟。
- 页面顺序固定，不做自由排序、常驻页、开机恢复上次页面或自动返回。
- 显隐与功能是否可用取交集：勾选天气/市场还需启用对应服务，图片/音乐仍需有效文件。
- 隐藏只影响设备页面入口，不删除文件或凭据、不自动停用服务，也不停止后台音乐。
  门户明确说明两者区别；停用联网服务仍使用各自的功能开关。
- 时钟、设置、在线更新、状态及启动恢复入口不能隐藏。隐藏当前页时安全退回时钟，
  重新显示页面不抢当前页面；语音导航和模态恢复也不能绕过显隐规则。
- 页脚与实际 BOOT 目的地使用同一页面选择逻辑，不能显示一个被跳过的目的地。
- 页面显隐在 dev.1 使用 schema v9，dev.2 连同音乐方式升级为 v10 独立双槽，迁移原有偏好，不覆盖旧记录；
  相同设置不重复写入，写入失败保留原值，其他表单不覆盖页面选择。

### 升级与回退

dev.1 使用 schema v9；dev.2 与正式版为持久保存音乐方式使用独立 schema v10 双槽，迁移 v9/v8
及更早的全部偏好，播放方式默认顺序播放，不复用旧记录或退役字段。
首次升级会迁移偏好。若之后回退 v0.29.0 或仅支持 v9 的 dev.1，旧固件的未来版本保护会使用默认偏好，
并拒绝改写这组设置；它不会自动恢复保留的旧记录。重新升级后可读取新版保存的偏好。
这不等于全部配置被清除；Wi-Fi、天气等独立存储不属于这组偏好。
迁移提交失败已纳入主机模拟，真实断电和跨版本回退仍需目标板验证。

### dev.2 追加：音乐日常使用

2026-09-27 用户要求同一版本多做几项优化，新增：

- 播放方式独立保存：顺序播放（默认）、单曲循环、列表循环。自然成功播完才决定是否
  续播；文件错误、取消或抢占不进入循环。手动下一首始终可用，修改模式不重启当前歌曲。
- 定时停止：15/30/60/90 分钟及取消，仅在播放或暂停中启用；暂停计时，切歌不重置，
  使用单调时钟，不受 NTP/RTC 调时影响。关闭网页不取消，停止/错误/抢占/重启后不续计时。
- 复杂操作只放网页媒体区。音乐页显示简短模式和剩余分钟，原有按键不变，无卡仍可保存
  播放方式，但不能启动播放或计时。不加流媒体、随机播放、后台唤醒或新设备菜单。

### dev.2 追加：门户读取与失败恢复

- 首次必要状态未加载时禁止提交；设置、地点目录或市场配置读取失败，可原地重试而不
  刷新整页、清空其他草稿。普通请求有界超时，POST 不自动重放。
- 保存超时/断线说明“结果尚未确认”，不能断言未写入；本地 OTA 必须先查看设备状态，
  重试时重新打开门户，不自动重复上传可能已成功的固件。
- 音乐模式表单不被每 3 秒歌单刷新覆盖；恢复默认值包括播放方式，不自动创建倒计时。

## 不纳入本版

温湿度历史、唤醒词、BLE、更多行情来源及 Light-sleep 均不混入。
功耗优化先取得真实电流与续航数据。当前只做有针对性的回归，不把主机模拟或构建成功
写成目标板的长期运行、异常复位、断电或 OTA 回滚验证通过。
