# 开发与发布流程

## 技术栈

- 只使用原生 ESP-IDF，不维护 Arduino 构建路线。
- 当前固定 ESP-IDF v5.5.3，目标芯片为 ESP32-S3。
- 项目源码按 ESP-IDF 组件拆分在 `src/`，应用入口位于 `src/app/`。
- 网络功能独立位于 `src/network/`，使用 ESP-IDF Wi-Fi、HTTP Server、NVS 与
  ESP-NETIF SNTP API。
- 设备偏好、电源规则与手动提前省电位于 `src/settings/`；偏好保存在独立 NVS 命名空间，纯策略逻辑由
  主机测试覆盖。
- 固件更新独立位于 `src/update/`：在线更新使用 HTTPS 清单、ESP-IDF CA 证书包和受控的
  HTTP Client/OTA 写入流程；设置门户使用受实体按键控制的临时网页，承载偏好、手机校时、
  已保存 Wi-Fi 查看与更换、独立凭据清除、本地 OTA 和可选 microSD 图片管理。两种 OTA 路径
  共用双 OTA 分区与回滚。
- 启动恢复位于 `src/recovery/`：纯策略负责复位分类、连续故障门槛、OTA 延迟确认和健康
  门槛，目标板适配只在 RTC 保留内存记录应用指纹、启动阶段与非敏感资源余量。恢复模式
  复用更新组件，但网页只注册 Wi-Fi 与本地 OTA 所需接口。
- 音频驱动、维护诊断与离线语音位于 `src/audio/`，使用板载 ES8311、ES7210、
  ESP-IDF I2S 和 Espressif ESP-SR MultiNet；16 kHz 单声道音频直接送入 MultiNet，
  不使用 AFE，也不创建第二套直接操作 codec 的采集链路。
- 可选 AI 语音 Beta 位于 `src/conversation/`，负责启用状态、API Key、受控模型与官方
  API Host 配置、双槽持久化、Realtime 事件和 WebSocket 客户端；scheme、路径与模型参数
  由固件按白名单组成，不接受完整用户 URL。同一有界会话复用一条 WebSocket
  和服务端上下文；采集和播放仍由 `src/audio/` 的同一个串行化 worker 独占 codec 与 I2S。
- microSD 图片源使用 ESP-IDF 原生 1-bit SDMMC 和 FatFs；`src/sd_image/` 负责启动
  扫描、PSRAM 缓存和只在用户确认时开放的有界导入事务，PBM/BMP 单色图片校验
  与解码位于 `src/image/`。
- `src/gallery/` 使用 HTTPS 固定清单下载公共演示图，限制主机、路径、清单大小、
  图片数量和总大小，每张图直接流入 microSD 导入事务并校验 SHA-256。
- U8g2、微雪 ST7305 适配器、Espressif QR Code、`esp_codec_dev`、ESP-SR 及其传递依赖
  都作为固定、可复现的外部构建依赖使用。

固定版本见 `tool-versions.env`。如果需要升级依赖，必须同时更新版本/提交哈希、重新完整
构建、实机验收并记录到 CHANGELOG。

涉及页面、提示语或实体按键的改动，应先阅读
[产品界面与交互设计规范](design-guidelines.md)，并同步更新界面效果图和主机逻辑测试。

## 依赖与版本控制

版本库只保存项目源码、文档、辅助脚本，以及由这些源码和固定开源依赖构建并经过实机
验证的发布固件。以下内容
由开发环境按需准备，不提交到版本库：

- ESP-IDF、编译器工具链和 Python 环境；
- U8g2、微雪示例、Espressif QR Code 等第三方源码；
- `build/`、`sdkconfig` 等本机构建结果；
- 社区固件和其他外部预编译文件。

第三方组件的来源、固定版本和许可索引记录在[第三方软件与字体声明](../NOTICE.md)，完整
许可文本保存在 [`LICENSES/`](../LICENSES/)。这些文件是二进制分发所需的合规文档，
不是第三方源码。发布固件只有在源码构建和实机验收均通过后，才能加入 `dist/vX.Y.Z/`。

`dist/` 按版本保存可追溯的发布文件；面向普通用户的 GitHub Releases 页面只保留最新
正式版本。自 v0.2.0 起，每个 `dist/vX.Y.Z/README.md` 还应展示该版本自己的效果图。

### 外部依赖目录

脚本按以下顺序选择依赖根目录：

1. 环境变量 `RLCD_DEPS_DIR`；
2. 当前 WSL 工作区中已存在的共享外部依赖目录；
3. 独立克隆仓库旁的 `../esp32-rlcd-firmware-deps/`。

`bootstrap.sh` 会输出最终选中的绝对路径，并且只写入该仓库外目录，不会把依赖复制到
版本库中。项目禁用 ESP-IDF Component Manager 的隐式下载；所有外部组件均由该脚本按
`tool-versions.env` 的提交哈希准备。

### v0.18.0 离线语音模型与升级边界

v0.18.0 固定使用 ESP-SR 2.4.7 和量化中文
MultiNet5，16 kHz 单声道音频直接进入 MultiNet，不启用 AFE、WakeNet 或常驻 VAD；如果
后续需要调整版本或模型，必须先更新固定版本、资源测量、
许可声明和本文，不能在开发机上临时下载一个未记录的模型继续发布。

启动时使用一个低优先级、一次性任务完成模型完整 SHA-256 校验、Flash 映射和 MultiNet
引擎创建；它不打开 codec、I2S、麦克风、扬声器或网络，完成后即退出。真正的采集和
`detect` 仍只由既有音频 worker 串行执行。模型预热不能排在闹钟播放请求前，预热尚未
结束时语音页只显示准备中。

项目继续保持 `IDF_COMPONENT_MANAGER=0`：`bootstrap.sh` 应在仓库外依赖目录准备并校验
ESP-SR、`esp-dsp`、`dl_fft`、cJSON 和所选模型的精确版本或内容摘要；
`bootstrap.sh --check` 必须能在不修改仓库的情况下确认依赖完整。新增二进制库、模型和
字体一样，需要在发布前核对再分发许可，并同步更新 `NOTICE.md`、`LICENSES/` 和许可检查，
但这些合规文件不应被组件管理器的临时缓存代替。

采集格式、MultiNet 调用和模型分区行为以 Espressif 的
[Speech Command Recognition](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/speech_command_recognition/README.html)
和 [Flash Model](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/flash_model/README.html)
文档为依据；项目文档只能补充本板槽位、交互和发布约束，不能改变模型要求。

ESP-SR 从标签为 `model` 的数据区域加载 `srmodels.bin`。v0.18.0 分区表在不改变两个
`0x300000` OTA 应用槽的前提下，固定把 `0x610000`—`0x90ffff` 的 `0x300000` 字节定义为
`model`。v0.16.0 及更早正式版本的分区表没有这条记录，但同一 16 MB 硬件上的该区域原本
未分配；v0.18.0 应用按相同地址注册并读取该区域，因此不必为了模型强制改写旧分区表。
应用和模型仍必须分别证明不超过 `0x300000`，不能覆盖相邻区域。

构建和打包流程自动确认：

1. 应用镜像不超过每个 OTA 槽，模型镜像不超过 `model` 分区；
2. `srmodels.bin` 的来源、模型集合、大小和 SHA-256 可追溯；
3. Factory 合并镜像在分区表规定的准确偏移包含 bootloader、分区表、应用和模型，读取
   回来的片段摘要与独立模型产物一致；
4. `-ota.bin` 仍然只是应用镜像，不得把模型拼接到应用 OTA 后面，也不得宣称它能更新
   分区表或模型；
5. 模型缺失、损坏或版本不兼容时，应用显示 `VOICE UNAVAILABLE` 并继续提供 RTC、页面、
   闹钟、网络和更新，不能启动循环重试或导致回滚。

在线更新和设置门户本地 OTA 仍只更新应用，不会安装 `srmodels.bin`；旧设备只走这两条
路径时，新应用必须安全启动并显示 `VOICE UNAVAILABLE`。USB `update-app.sh` 则是 v0.18.0
的固定开发更新路径：一次 `write-flash` 同时把应用写入 `0x10000`、模型写入 `0x610000`，
成功后只清除 `0xd000` 的 OTA 选择数据，不覆盖 `0x9000` 的 NVS，也不改写 `0x8000` 的
旧分区表，因此保留 Wi-Fi 和设备偏好。默认模型为 `build/srmodels/srmodels.bin`，必要时
可用 `--model` 指定同一校验目录中的模型。

从 v0.7.0 或更新版本迁移到当前 v0.24.0 的 USB 验收流程如下；离线语音模型仍是
v0.18.0 首次引入的同一发布边界：

1. 先执行 `./scripts/build.sh`，再确认 `build/SHA256SUMS` 同时校验应用和
   `srmodels/srmodels.bin`；
2. 关机后按住 `BOOT` 再按 `PWR`，把设备以 ROM 下载模式连接电脑；
3. 执行 `./scripts/update-app.sh --port COMx --confirm`；使用发布目录时传入版本化的
   `--firmware` 和 `--model` 文件。两个文件与发布目录的 `SHA256SUMS` 放在一起时，也可以
   只传 `--firmware`，脚本会自动选择同版本 `-model.bin`；
4. 正常开机，确认原有 Wi-Fi 和设备偏好仍在，再从“语音”页验证模型和指令。

发布目录命令示例：

```bash
./scripts/update-app.sh \
  --port COM5 \
  --firmware build/release/v0.25.0/esp32-rlcd-firmware-v0.25.0-ota.bin \
  --model build/release/v0.25.0/esp32-rlcd-firmware-v0.25.0-model.bin \
  --confirm
```

首次安装、完整恢复和需要改写为新分区表时，使用包含模型的 v0.25.0 Factory 镜像；
`build.sh` 必须逐字节确认 Factory 在 `0x610000` 包含同一 `srmodels.bin`。已通过
`update-app.sh` 或 Factory 安装兼容模型的设备，后续纯应用 OTA 可以继续复用它；改变
模型内容、区域大小或不兼容 ABI 时，必须再次提供 app+model USB 更新或独立、断电安全且
可回滚的模型更新机制，首版不提供在线模型更新。

## 常用命令

```bash
./scripts/bootstrap.sh --check
./scripts/configure.sh
./scripts/check-repository.sh
./scripts/check-licenses.sh
./scripts/test.sh
./scripts/build.sh
./scripts/package-release.sh vX.Y.Z
./scripts/flash.sh --port COM5 --confirm
./scripts/update-app.sh --port COM5 --confirm
./scripts/set-rtc.sh --port COM5
```

具体步骤见[开发烧录指南](flashing.md)，不从聊天记录还原命令。

`configure.sh` 调用固定版本 ESP-IDF 的 `menuconfig`，修改写入已忽略的本地 `sdkconfig`。
项目可公开的默认值保存在 `sdkconfig.defaults`；个人固定热点密码不得写入该文件或提交到
Git。删除 `sdkconfig` 后会恢复项目默认值。

`package-release.sh` 在 `build/release/vX.Y.Z/` 生成待上传文件，包括固件、校验值、
`LICENSE`、`NOTICE.md` 和完整许可文本压缩包，并在返回成功前自检全部附件。v0.18.0
及更新版本只消费 `dist/vX.Y.Z/` 中已经验收的 Factory、OTA 和同版本 `-model.bin`；脚本
核对模型清单、Factory 固定偏移中的模型内容和三项发布哈希，再复制到打包目录。最终目录的
`SHA256SUMS` 由脚本针对三项二进制重新生成，可直接供 `update-app.sh` 校验。它不会创建
或修改 GitHub Release，也不会更改仓库可见性。

### 构建版本与更新通道

仓库默认构建版本为 `0.25.0`。需要构建其他版本时，通过环境变量覆盖，不直接为一次
候选构建修改 `CMakeLists.txt`：

```bash
RLCD_PROJECT_VERSION=0.26.0-dev.1 ./scripts/build.sh
RLCD_PROJECT_VERSION=0.25.0 ./scripts/build.sh
```

版本必须是固件可比较的 SemVer，且不带文件名使用的前导 `v`：

- 设备默认读取 `https://mcu.taifua.com/esp32-rlcd/firmware/stable.json`；只有设备偏好中
  显式启用开发者测试通道后才读取 `testing.json`；
- SemVer 不自动选择通道。稳定清单只允许 `0.25.0` 这类正式目标，测试清单用于
  `0.26.0-dev.1`、`0.26.0-rc.1` 等候选，也可在转正式期间指向正式目标。

预发布验证先上传版本化 `-ota.bin`，核对大小和 SHA-256，再更新 `testing.json`。正式
发布必须从同一份已实机验收的源码构建正式版本，重新核对产物差异、大小与 SHA-256 后
更新 `stable.json`；不要让清单提前指向尚未上传或尚未验收的文件。v0.9.0 没有在线更新
客户端；这类设备可从原本地更新入口直接上传当前正式 OTA，也可通过 USB 写入。

## 版本发布清单

1. 确定 SemVer；正式构建必须显式使用 `RLCD_PROJECT_VERSION=X.Y.Z`，并确认版本不含
   预发布标识。设备默认读取 `stable.json`；只有显式加入 Beta 的设备读取
   `testing.json`。
2. 在 `CHANGELOG.md` 把 `[Unreleased]` 内容整理为对应正式版本。
3. 执行 `./scripts/bootstrap.sh --check`。
4. 执行 `./scripts/check-repository.sh`，确认仓库边界、文档链接和历史发布哈希正常。
5. 执行 `./scripts/check-licenses.sh`；新增或升级组件、字体时先更新 `NOTICE.md`、
   `LICENSES/` 和检查脚本。
6. 执行 `./scripts/test.sh`，确认纯逻辑测试通过。
7. 执行 `RLCD_PROJECT_VERSION=X.Y.Z ./scripts/build.sh`，确认无编译错误且应用描述中的
   版本正确。
8. 核对 `build/SHA256SUMS`。
9. 首次迁移使用 Factory 镜像完整烧录；后续同时验证在线更新、设置门户本地 OTA 和保留
   NVS 的串行应用更新，具体步骤见[开发烧录指南](flashing.md)和
   [固件安装与更新](firmware-update.md)。
10. 验证屏幕、RTC、农历、温湿度、电池 ADC、PSRAM 和串口日志。
    含联网功能的版本还必须验证首次配网、错误密码恢复、自动 SNTP、RTC 写后回读、断电
    重连、`NORMAL` 常连、`SAVING` 临时联网收尾、`GET_NETWORK`、USB `RESET_WIFI`、
    系统中心页面和上下文长按操作，并确认日志不包含家庭 SSID 或密码。含 microSD 改动的
    版本还必须分别验收无卡、只读启动、
    用户确认导入、中断恢复、数量上限和关机插拔。首次发布云端语音 Beta 时，至少必须在
    目标板验证设置门户粘贴与保存专用 Key、北京共享 Host 加默认模型的端到端连接、转写、
    文字显示和 24 kHz 播放，并确认既有日常页面仍可使用。状态接口与日志不得包含完整 Key、
    请求头、PCM 或对话正文。停用与离线回退、错误 Key、第二模型、其他受控 Host、长输入、
    取消、中途断网、连续资源回收和闹钟抢占等完整矩阵记录在[开发计划](roadmap.md)，完成前
    功能保持 Beta，且每次发布必须在 Changelog 和版本说明中列出尚未实机覆盖的边界。
    涉及多轮会话的版本还必须验证同一 WebSocket 的上下文连贯、播放中续问、
    `FOLLOW-UP` 的 `KEY` / `BOOT` 语义、第 5 轮、30 秒续问、5 分钟下一轮准入边界和
    在途回答不被总时限截断，
    并确认会话结束后的网络、codec、内存和性能锁全部回收。
    Host、URL、模型和表单的拒绝路径还必须由主机测试覆盖。涉及对应路径的后续改动应补做
    针对性实机回归；移除 Beta 标记或更改默认模型前必须完成全部矩阵。
    涉及天气交互时，还要验证天气页 2 秒长按在 `NORMAL` 与 `SAVING` 下均能主动获取，
    请求期间保持固定布局，失败保留同地点缓存，操作结束按当前电源规则收尾网络。
    涉及启动恢复时，必须验证同一镜像连续 3 次异常复位后的下一次启动进入恢复；计划内
    OTA 重启、断电、棕断、USB/JTAG 复位和镜像变化不误触发；`KEY` + `PWR` 手动恢复与
    `BOOT` + `PWR` ROM 下载互不混淆；恢复模式只保留在线更新、设置和精简门户。按键不可用
    时还要确认精简门户自动开启。待验证 OTA 只能在显示和按键就绪、首轮周期任务完成、
    至少出现一个页面且运行满 15 秒后确认，失败每 5 秒重试；连续稳定 60 秒后才清除故障
    计数。完成前不得写入实机通过结论。
11. 只有与本次发布范围对应的必需实机检查通过后，才把 Factory、OTA 与同一次构建生成的
    版本化 `-model.bin` 复制到 `dist/vX.Y.Z/`，用三条 `SHA256SUMS` 保存大小、摘要、
    构建依赖和验收记录。模型与固件一样是受版本控制的正式发布产物；`build/` 中间文件
    仍不提交。
12. 按[发布固件安装指南](user-install.md)重新执行发布路径，确认普通用户命令和文件名一致。
13. 执行 `./scripts/package-release.sh vX.Y.Z`，检查 `build/release/vX.Y.Z/` 中的全部附件
    和 `RELEASE_SHA256SUMS`。
14. 检查 Git 暂存内容，确保没有第三方源码、`build/`、`sdkconfig`、密码或外部固件。
15. 提交并创建 `vX.Y.Z` 标签。
16. 创建 GitHub Release，上传打包目录中的 Factory/OTA 固件、校验文件、效果图、
    `LICENSE`、`NOTICE.md` 和许可文本压缩包；v0.18.0 及更新版本同时上传同版本的
    `-model.bin`。
17. 把同一 OTA 固件发布到版本化 HTTPS 地址，核对远端大小和 SHA-256 后再原子更新
    `stable.json`；不得让正式清单指向测试文件。
18. 用上一正式版本在线检查并确认能发现新版本，但安装仍需实体按键确认。
19. GitHub Releases 只保留最新正式版本；删除旧 Release 条目时保留 `dist/` 历史文件。
20. 仓库可见性是独立的人工决定；构建、打包和发布脚本均不得自动切换 Public/Private。

## 安全约定

- 构建与烧录是两个明确分开的动作。
- 烧录必须显式传入 `--confirm`，且脚本必须验证目标 VID/PID。
- 不默认执行 `erase-flash`。
- 家庭 Wi-Fi 密码不得写入源码、构建配置、构建日志或 Git；运行时凭据只允许由配网页面
  写入设备 NVS。临时配网热点可在已忽略的本地 `sdkconfig` 中设置固定密码，但默认应
  留空并在运行时随机生成；固定值会嵌入固件，不应视为秘密。当前 NVS 未加密，这一限制
  必须在面向用户的文档中明确说明。
- 设置门户只返回已保存 SSID，密码输入不回传、预填或记录。更换 Wi-Fi 时先在 RAM 中
  验证完整候选凭据，取得 IPv4 后才替换 NVS 记录；失败必须保留旧配置，不得在验证前
  删除或覆盖它。
- 任何配网或网络日志都不得输出家庭 SSID、密码或 HTTP 请求正文；调试状态只报告是否
  已配置、状态名、错误码和非敏感长度。
- `sdkconfig.defaults` 将默认和编译期最高日志级别都锁定为 `INFO`，仓库检查不得允许
  `DEBUG` 或 `VERBOSE` 覆盖。提高日志级别不能作为排障捷径；需要额外诊断时只增加经过
  审核的非敏感标量状态，不能记录凭据、Authorization 头、请求正文、PCM、转写或回复。
- 二维码原文包含临时热点密码；外部组件的输入日志必须在编译时关闭，`build.sh` 会检查
  最终组件归档，发现相关日志字符串时拒绝生成可用构建结果。
- 在线更新必须通过 ESP-IDF CA 证书包验证 HTTPS；清单的项目、硬件、通道、版本、下载
  主机、大小和 SHA-256 任一不匹配都不得写入或切换启动槽。安装前必须重新读取清单，
  自动流程只能检查，不能下载或安装。
- 所有主动 `esp_restart()` 路径都必须先标记计划内重启，避免被启动恢复误计为故障。待验证
  OTA 不得在应用入口立即确认，只能通过可主机测试的 15 秒启动门槛；恢复模式禁止确认，
  确认 API 失败要按固定 5 秒间隔重试。连续故障记录只放 RTC 保留内存，不得用 NVS 写入
  循环构成跨断电锁定。
- 不改写或提交仓库外的上游参考源码。
- 原始麦克风 PCM 不得写入日志、Flash、NVS 或 microSD。离线模式不得发送 PCM；AI
  语音 Beta 只在用户主动开始的本次有界会话中通过已验证证书的 TLS WebSocket 发送，
  不得让“不持久化”
  掩盖上传事实。语音日志只允许记录会话状态、不可还原的指令编号、耗时和错误码；任何
  调试采样、转写或回复都不得进入正式构建或发布产物。
- 云端 API Key 不得由状态接口返回、网页预填或日志记录；空白保存只保留既有 Key，关闭
  云端也保留 Key，清除使用独立确认并同时停用云端、恢复默认模型与北京共享 Host。API
  Host 只接受北京/新加坡的百炼共享域名或单标签 Workspace 专属域名；设置门户不得接受
  scheme、路径、端口、IP、代理或任意域名。模型只能来自经过实现与验证的枚举，不能把
  任意模型名拼入请求。当前 Flash 与 NVS 未加密，文档必须明确物理读取风险，并建议专用、
  可轮换的 Key、消费保护和设备转让前吊销。完整边界见[云端语音 Beta](cloud-voice.md)。

## 网络功能验收

当前网络设计与操作说明见[自动配网与网络校时](network-time.md)。正式发布前至少覆盖：

1. 空白 NVS 启动后屏幕显示默认热点名称、随机密码和固定入口地址；另外验证自定义名称、
   关闭设备后缀与固定密码配置；
2. Android 和 iOS 扫描二维码均能识别热点名称和密码；特殊字符转义正确，二维码四周
   静区完整，扫码后也可按文字信息手动连接；
3. 手机连接临时热点，提交开放网络和 WPA2/WPA3 Personal 凭据的正常/错误边界；
4. 正确凭据下取得 DHCP 地址，SNTP 按设置的 UTC 偏移取得本地时间，PCF85063 写入后
   秒数持续增加；默认偏移为 UTC+8；
5. 家庭 Wi-Fi 离线时首屏、RTC、月历、温湿度、按键和离线语音保持可用，不自动开放配网
   热点。实际 `NORMAL` 取得 IPv4 后使用 `WIFI_PS_MIN_MODEM` 保持连接，断线使用
   1、5、15 分钟退避并在之后每 15 分钟重试；Wi-Fi 已连接但 NTP 不可达时保持 STA，
   将同步失败标记为不同阶段且不打断首屏。因低电或手动请求生效的 `SAVING` 不自动联网
   或重试；错误凭据只能通过用户明确执行重新配网来替换。首屏图标只在 STA 取得 IPv4
   后显示，断线、丢失 IP 和主动停网后立即隐藏；`NORMAL` 网络事务结束后图标与连接均
   保持，`SAVING` 手动事务结束后隐藏。停止后的迟到 `GOT_IP` 事件不得重新点亮图标，
   配网和设置 SoftAP 不计入；“状态”页用独立的 `TIME SYNC` 和 `WI-FI` 行区分历史同步
   与当前连接；
6. 新判定记录首次在 `RTC` 行显示备用结果 `UNTESTED`；安装 RTC 备用电池并真实断电后，在任何
   NTP 操作前显示 `VERIFIED`，移除或耗尽备用电池后的真实断电显示 `FAILED`；两种情况
   都保留 NVS 网络凭据；`NORMAL` 自动连接并恢复时间，`SAVING` 等待用户手动校时；
7. 设置门户期间家庭 STA 暂停，网页准确显示已保存 SSID 而不冒充当前连接，且永不返回、
   预填或记录家庭 Wi-Fi 密码。更换网络时，正确凭据取得 IPv4 后才写入 NVS；错误密码和
   超时都保留旧凭据，失败后门户可继续修正。候选连接引起 SoftAP 信道切换时，手机可以短暂断开，
   重连门户后应能确认最终结果；成功后关闭门户并按实际状态恢复：`NORMAL` 使用新网络
   校时并保持连接，`SAVING` 完成本次主动校时后关闭无线，全程不重启。没有修改网络时
   直接关闭门户也必须按同一规则恢复。
   USB `RESET_WIFI` 与门户的“清除 Wi-Fi”仍是独立的恢复入口，
   都只清除项目网络命名空间并原地进入首次配网；门户操作必须二次确认，且不会重置其他偏好；
8. `BOOT` 默认在首屏与月历之间切换，microSD 存在有效图片时条件加入
   图片页。`BOOT` 能从任意系统页返回首屏；`KEY` 只进入并循环
   “状态、语音、设置、在线更新”四个系统页，所有次级页面 30 秒超时符合规范；
9. “状态”页长按 `KEY` 2 秒触发即时校时；“语音”页长按 2 秒并松开后执行最长 5 秒的
   离线识别，监听中短按 `KEY` 可提前结束，活动阶段短按 `BOOT` 可取消且清除临时音频；
   AI 语音满足联网条件时，同一 WebSocket 中最多进行 5 轮，回复后短按 `KEY`
   续问、短按 `BOOT` 结束，并覆盖 30 秒续问、5 分钟准入边界及在途回答保护；
   “设置”页长按 `BOOT` 2 秒切换手动提前省电，长按 `KEY` 3 秒开启设置门户。其他页面
   未提示的 `KEY` 长按以及“设置”页之外的运行时 `BOOT` 长按均无操作，松开也不会误判

10. “在线更新”页按住 `KEY` 2 秒可检查；发现新版本后再按住 2 秒进入 `REVIEW`，确认页
    必须按住 3 秒才安装。`NORMAL` 复用保持中的连接，`SAVING` 只为手动操作临时连接；
    自动联网只更新检查结果，不切换页面、不下载且不静默安装；
11. 所有版本默认接受 `stable.json`，显式启用开发者测试通道后才接受 `testing.json`。
    稳定通道不得提供预发布目标；错误项目、硬件、通道、版本、最低版本、URL 主机、大小
    和 SHA-256 均被拒绝，同版本与降级也不安装；
12. 在线检查、连接和确认阶段短按 `BOOT` 可以取消；写入开始后按键不再中断。正确 OTA
    镜像显示实际百分比、校验后重启并保留 NVS/Wi-Fi；断网、截断响应和摘要不匹配仍保留
    当前启动槽；故意不确认的新镜像能由 Bootloader 回滚；
13. 手动提前省电只由设备“设置”页保存，默认关闭；设置门户不重复提供该开关，提交其他
    字段时必须保留它。门户可保存 UTC 偏移、摄氏/华氏单位、播放音量、每周闹钟和更新
    通道，可用手机时间写入 RTC，也可查看、更换或独立清除 Wi-Fi；更新通道默认稳定、
    闹钟默认关闭。
    schema v6 使用 `manual_saving_requested` 布尔字段和
    `cfg6_a` / `cfg6_b` 双槽；schema v5 的 `AUTO(0)`、`NORMAL(2)` 迁移为关闭，
    `SAVING(1)` 迁移为开启，schema v1—v4 的 `NORMAL(0)` / `SAVING(1)` 分别迁移为
    关闭 / 开启，其他偏好保持不变；单槽损坏后
    启动会读取完整槽并修复冗余，健康双槽启动不重复写入；保存和破坏性操作均须按页面
    说明确认；
14. `NORMAL` 显示秒并按 1 秒读取 RTC、5 秒读取环境、30 秒读取电池，同时保持家庭 Wi-Fi
    连接并允许自动校时、网络重试和版本检查；确认驱动使用 `WIFI_PS_MIN_MODEM`，不得为
    常连无理由改为 `WIFI_PS_NONE`。`SAVING` 不显示秒，按 60 秒读取 RTC 与环境，并约每
    10 秒读取电池以便及时判断自动低电进入或恢复条件，且不自动联网；手动网络事务完成后
    必须关闭无线。电压采样本身不得强制刷新静态页面。启用闹钟后只把 RTC 检查提高到每秒
    一次，不增加屏幕刷新。两种实际状态下按键、离线语音、手动校时、设置门户和手动更新
    都可用，固件不得使用 Light-sleep 或 Deep-sleep；
15. 单个闹钟按设置时区下的 RTC 本地时间和每周掩码触发；`NORMAL`、`SAVING` 与
    断网时都能响，`BOOT` 停止、首次 `KEY` 延后 5 分钟、第二次不再延后、60 秒自动停止；
    RTC 无效、错过目标分钟和物理关机期间不补发，同一规则同一天重启不重复响；闹钟模态
    期间原先已按住的按键不会误触发，临时音频诊断或离线语音会安全结束，设置门户或 OTA 不会让
    RTC 读写交错；
16. 设置门户能够从同一临时热点上传 `-ota.bin`；短按 `BOOT` 能在等待上传时安全取消，
    上传错误文件和中断传输不会改变当前启动槽，无互联网时仍可完成本地 OTA；五分钟截止
    后拒绝新请求，已开始的短设置事务在有限清理窗口内完整结束，长 OTA 到期后中止且不切槽；
17. 关机后按住 `BOOT` 再按 `PWR` 仍能正常进入 ROM 下载模式；此时应用未运行，屏幕不
    显示写入进度；
18. Factory 镜像重新烧录后 NVS 被清空并能重新完成首次配网；在线更新、设置门户本地

19. 空白 NVS 的配网二维码 60 秒后恢复离线首屏，临时热点在 5 分钟后关闭；RTC 无效时
    首屏稳定显示占位符，系统中心和其他本地功能仍可操作；
20. 串口和构建产物的字符串检查不包含实机家庭 SSID、家庭密码或二维码中的临时热点密码。

8. 操作过程中按住任一按键跨越取消或结果页边界时，必须先松开并重新按下，不能把释放

## v0.18.0 自动低功耗验收边界

原计划中的 v0.17.0 没有单独发布，自动低功耗与离线语音一并进入 v0.18.0。主机测试能够
确认纯逻辑和记录迁移，但不能替代目标板上的频率、外设联动与外部电流测量；以下清单继续
作为回归和证据边界。

1. 空白 NVS 和恢复默认值后的“手动提前省电”均为关闭；该开关只在设备端保存，设置门户
   不重复提供，提交其他偏好时必须保留现值。固件不提供三态电源策略或强制 `NORMAL`。
   设备 `SETTINGS` 页根据当前证据
   显示 `NORMAL`、`NORMAL | USB`、`SAVING | MANUAL` 或 `SAVING | LOW BAT`；
2. 从 v0.16.0 的 schema v4 双槽分别准备旧 raw `NORMAL(0)` 和 `SAVING(1)`，升级后确认
   前者映射为手动关闭、后者映射为手动开启；从已经安装的 v0.17.0 beta schema v5 分别
   准备 `AUTO(0)`、`SAVING(1)`、`NORMAL(2)`，确认映射为关闭、开启、关闭。schema v6
   使用严格 0/1 的 `manual_saving_requested` 与 `cfg6_a` / `cfg6_b` 双槽，时区、温标、
   音量、更新通道和闹钟规则保持不变；单槽损坏仍可回退，迁移中断不得提前推进 schema
   标记或用默认值覆盖可恢复的旧记录；
3. 电源决策优先级固定为“USB 数据主机 > 手动提前省电 > 自动低电”。数据主机存在时显示
   `NORMAL | USB`；没有数据主机且手动请求开启时显示 `SAVING | MANUAL`；手动请求关闭后
   仍低电时显示 `SAVING | LOW BAT`，不是强制 `NORMAL`。手动与低电同时成立时以用户明确
   请求作为显示原因，但自动低电规则始终保留；
4. 冷启动在取得首个有效电量前先保持 `NORMAL`；首个有效读数不高于 20% 时直接使用
   `SAVING | LOW BAT`，高于 20% 时使用 `NORMAL`，重点核对 20% / 21% 边界；
5. 运行期间从 `NORMAL` 进入低电 `SAVING` 必须连续两次取得不高于 20% 的有效读数，
   从低电 `SAVING` 恢复 `NORMAL` 必须连续两次取得不低于 25% 的有效读数。21%—24%
   保持当前实际状态；未达到待切换阈值的读数、无效读数或读取失败会打断未完成的连续
   计数，防止临界值抖动；
6. 任意 `SAVING` 检测到发送 SOF 的电脑 USB 数据主机时立即恢复 `NORMAL | USB` 并取消
   低电待切换计数；不再检测到主机后立即读取一次电量，再按手动请求与新的连续样本判断。
   分别用电脑数据连接、墙充、充电宝和纯充电线验证边界：后三者因原板没有 VBUS 或充电
   状态输入而不得误报为数据主机，只能继续按电量规则运行；
7. 实测插线后百分比快速上升、拔线后快速回落时，同时记录 GPIO4 还原电压。页面、日志和
   文档均不得把端电压抬升解释为实际容量瞬增，也不得据此声称已检测到普通充电器或显示
   可靠充电状态；需要精确荷电状态必须增加电量计硬件；
8. 实际状态切换时，秒显示、RTC/环境/电池采样、联网保持、后台更新检查和 CPU 策略同步
   切换，不生成重启；进入 `SAVING` 时已有手动网络事务先完成再关闭无线，恢复 `NORMAL`
   时自动连接并保持家庭网络。`SAVING` 约每 10 秒读取电池，以及时判断自动低电进入或
   恢复条件，但不因此强制刷新静态页面；
9. 目标板启动日志确认 ESP-IDF 动态频率范围为 80—240 MHz。实际 `NORMAL` 持有最高频率
   锁并保持 240 MHz，实际 `SAVING` 释放该锁以允许 DFS；反复跨状态切换时锁状态和日志
   一致，不发生死锁、错误累积或任务停顿；
10. 两种实际状态均保持 Light-sleep、Deep-sleep 和自动 Tickless Idle 关闭。按键、USB
    Serial/JTAG、屏幕刷新、RTC 闹钟、音频、microSD、设置门户以及本地/在线 OTA 按既有
    验收路径回归，`SAVING` 不得被描述为会关闭全反射屏或使本地功能不可用；
11. `./scripts/test.sh` 覆盖布尔偏好与表单、schema v1—v5 迁移、schema v6 编解码、冷启动
    边界、20% / 25% 滞回、连续两次确认、无效采样复位、USB 数据主机最高优先级、手动
    请求与低电并存以及关闭手动请求不强制 `NORMAL`；ESP-IDF 正式构建还需确认 PM 配置、
    组件依赖和 240 MHz 上限断言通过；
12. 在断开 USB、仅由受控电池供电的统一条件下，使用外部电流表或功耗分析仪分别测量
    `NORMAL` 已连接、`NORMAL` 断网重试、`SAVING | MANUAL` 与 `SAVING | LOW BAT`。
    记录稳态电流、联网与屏幕刷新峰值，并覆盖闹钟开关、microSD 有无、Wi-Fi 任务、设置
    门户和音频空闲；只有取得可复现数据并明确电池容量后才估算续航，本项目前仍视为外部
    仪表待验收；
13. 在 `SETTINGS` 页按住 `BOOT` 1 秒显示明确提示，满 2 秒只切换并保存一次手动提前省电
    开关；提示出现后未满 2 秒松开、继续长按或长按后松开均不得触发返回首屏。操作不启动
    热点、不重启，保存后立即尝试热应用并保持页面；应用成功后才显示完成，暂时无法应用时
    明确显示等待重试，保存失败时原偏好和运行态不变。保存前必须重新读取最新完整设置，
    只修改 `manual_saving_requested`，避免覆盖门户刚保存的时区、温标、音量、更新通道或
    闹钟。原 `KEY` 短按切页、按住 3 秒开启门户以及其他页面的长按动作保持不变；两个按键
    交叠按下时不得同时切换手动省电和开启门户，结果页期间开始的任意按键也必须完整松开后
    才能恢复普通操作。

本版实机已确认自动规则不需要额外选择“自动模式”，低电时会进入 `SAVING` 并隐藏秒数，
手动提前省电仍由设备端控制；用户完成插线、拔线和重新启动观察后确认功能正常。实测中
插线后估算值会快速上升，拔线后又快速回落，与 GPIO4 端电压估算边界一致。尚未使用外部
电流表测量稳态功耗、峰值和续航，也没有把普通充电器或端电压上升记录为已识别充电状态。

## v0.18.0 首版离线语音验收

首版只提供用户主动发起的短时离线指令，不包含唤醒词、常驻监听、自由问答、云端识别、
在线模型更新或有持久副作用的语音操作。以下清单同时保存已经实现的约束与后续回归边界，
实机完成项单独记录在清单之后。

1. “语音”页空闲状态明确显示语音是否就绪并提示按住 `KEY` 2 秒，满 2 秒进入
   `RELEASE KEY`；只有完整松开后才开始一次最长 5 秒的监听。未满 2 秒松开不启动也不
   切页，同一次长按释放时不产生短按；
2. 准备和识别阶段短按不落入页面导航；监听阶段短按 `KEY` 提前结束发音并开始识别，
   任一活动阶段短按 `BOOT` 取消。结果显示至少 2 秒，会话期间暂停 30 秒页面超时，退出
   后恢复既有 `BOOT` 返回和 `KEY` 系统页循环；
3. 首版指令白名单仅映射到主界面、日历、存在时的图片、状态和设置页面，另允许取消
   当前会话；未知、低置信度、图片缺失和会话已失效时保持原页面。不得触发 OTA、清
   Wi-Fi、设置
   热点、图片删除、偏好保存、省电切换、闹钟停止或延后；
4. ES7210 以 16 kHz、signed 16-bit、四槽 TDM 采集，实机分别确认物理 MIC1/MIC3 对应
   slot 0/2；首版只提取 slot 0 作为单声道直接送入 MultiNet，slot 2 保留用于电平判断和
   维护诊断。不得把四槽原始流直接交给识别器，不使用 AFE，也不增加 24 kHz 软件重采样；
5. codec 和共享 I2S 时钟始终只有一个所有者。语音采集、回环诊断、扬声器播放与闹钟
   互斥，反复在 16 kHz 麦克风和既有 24 kHz 播放路径间切换后，两路麦克风、诊断和闹钟
   都必须恢复正常；扬声器不可用或播放音量为 `0%` 不影响纯麦克风指令；
6. 闹钟在准备、监听、识别和结果四个阶段分别触发时，都必须在可测的有限时间内取消
   会话、清理 MultiNet 和待处理结果，再开始提醒音；建议目标为报警输出请求后 1 秒内
   开始声音。
   闹钟结束后不执行迟到指令，跨模态按住的按键完整松开前保持门控；
7. 启动期低优先级一次性任务只负责模型校验、映射和引擎创建，不得占用 codec 或阻塞
   闹钟 worker；既有音频工作任务串行负责采集、slot 0 单声道提取和 MultiNet detect，
   不创建第二个 codec 采集或识别任务。预热完成后的 MultiNet 引擎持续复用，空闲时不采集。
   连续执行 20—50 次成功、未识别、取消和报警抢占，记录 PSRAM/内部 RAM 最小余量、任务
   栈高水位和碎片趋势，不得有持续泄漏；
8. 每次结束、取消、失败和闹钟抢占都清零临时 PCM 并 clean MultiNet；串口、NVS、
   microSD、HTTP 请求和构建字符串中均不存在可还原音频。设备空闲时不读取麦克风，也不
   显示会让用户误以为麦克风常开的图标；
9. 断网、没有已保存 Wi-Fi、无互联网和无 microSD 时，所有白名单指令仍可使用且不会
   启动网络。`SAVING | MANUAL` 与 `SAVING | LOW BAT` 下允许一次主动会话，期间临时持有
   最高 CPU 频率，完成或异常退出后释放；确认页面仍显示原实际电源状态，并测量低电时的
   峰值和 brownout 风险；

### 语音可靠性候选验收

后续候选不增加用户页面、语音指令或持久化数据，只新增 `GET_VOICE` 和
`RESET_VOICE_DIAG` 两个开发者 USB 命令。`GET_VOICE` 以同一锁内快照返回当前状态与累计
汇总；`RESET_VOICE_DIAG` 只在没有语音会话运行时清空易失计数。内存最小值按 worker
开始、工作区分配后、监听期间每 500 ms 和清理后观测，不表示无法采到的瞬态精确峰值。
`capture_ms` 只统计已经送入 MultiNet 的帧，不含麦克风打开与 settle chunks；`wall_ms`
是 audio worker 进入到资源清理后的时长，不含长按、等待松开、结果显示或闹钟实际出声。
任务栈高水位是该共享 worker 自创建以来的历史最小余量，不是每次会话独立峰值。以上
输出均不包含 PCM。

目标板安装候选后，在 WSL 执行：

```bash
./scripts/collect-voice-diagnostics.sh --port COM5
```

打开原生 USB 串口可能使 ESP32-S3 重新启动，也会提供 USB 数据主机证据，使设备处于
`NORMAL | USB`；因此这套流程只建立 USB/NORMAL 基线，不能用来证明低电 `SAVING` 功耗
或 brownout 风险。脚本轮询 `GET_VOICE`，确认模型、引擎和麦克风就绪后先要求一次不计入
结果的预热，再验证 `RESET_VOICE_DIAG` 已清零。随后它逐项显示下一个场景，只有观察到
对应 audio worker 会话完成才前进，并把主机测试标签和该次五行快照写入忽略提交的
`build/`。完整串口流不会写入文件。

固定矩阵包含 50 个已经松开 `KEY`、真正启动 audio worker 的会话。长按后尚未松开时
取消、模型不可用或 `audio_voice_start()` 被其他事务拒绝都不计入 50 次，应另行记录：

| 场景 | 次数 | 操作 |
| --- | ---: | --- |
| 近距离、安静 | 11 | 逐条说出固件内的 11 个固定短语 |
| 较远距离 | 11 | 在固定距离下重复同一组短语并记录距离 |
| 日常背景声 | 11 | 在固定噪声来源和位置下重复同一组短语 |
| 无关中文 | 5 | 使用不在白名单中的短句，观察是否误接受 |
| 静默 | 4 | 启动后不说话，等待或提前结束 |
| BOOT 取消 | 4 | 开始监听后、结果出现前按 `BOOT` 取消 |
| 闹钟抢占 | 4 | 将闹钟设在下一分钟，在目标分钟前不足 5 秒松开 `KEY` 开始监听 |

11 个固定短语为“回到主页、查看时间、打开日历、查看日期、查看状态、设备状态、打开
图片、查看图片、打开设置、查看设置、取消”。若设备没有有效图片，“打开图片”和“查看
图片”仍应被识别，但策略结果应为目标不可用而不是跳转。5 个无关短句固定为“今天天气
怎么样、播放音乐、打开蓝牙、设置闹钟、更新固件”。

汇总结果来自 MultiNet/audio worker，早于应用层页面策略：“取消”应记录为
`matched command=6`，而不是 `cancelled`；无图片时两条图片短语仍记录为
`matched command=4`；`cancelled` 只表示运行中的 worker 被实体操作或闹钟中断。脚本按
这套底层语义核对每个标签，声学预期不一致会被记录为 mismatch，但不会掩盖后续样本。

每次闹钟抢占后先按 `BOOT` 停止正在播放的提醒，再把闹钟重新配置到新的下一分钟；同一
日期、同一规则只触发一次，不能直接等待它重复。语音 worker 最长只监听 5 秒，因此必须
在目标分钟前不足 5 秒才松开 `KEY`，否则会话会先正常结束。设置操作较慢时可把脚本的
单例等待改为 `--session-timeout-seconds 300`。

脚本自动保存开始时间、串口、候选版本和 `NORMAL | USB`，并在近距、远距和背景声场景
开始时分别要求输入实际距离或噪声来源、位置与大致强度。验收记录还应保存最终五行
`GET_VOICE` 汇总。
会话总数应为 50，各结果计数之和应与总数一致，错误会话与 CPU
性能锁获取、释放失败均应为 0；设备不得重启、brownout 或卡死，任务栈余量不得持续
下降，内部 RAM、PSRAM 和最大连续块在排除首次惰性分配后不得呈持续单向下降。误接受、
拒绝按场景逐项记录，不用单一百分比掩盖测试条件。USB 日志不能测量闹钟从请求到扬声器
出声的延迟；需要该数据时应使用外部录像、录音或逻辑分析手段。外部电流峰值同样需要
功耗仪表，串口统计不能替代。

脚本完成时的 `mechanical_checks=pass` 只表示会话计数、结果计数和、错误、CPU 性能锁、
栈非零以及严重故障/意外复位检查通过；资源趋势明确标为 `resource_review=pending`。审查
每例保存的 internal RAM、PSRAM、最大连续块和栈序列后，才能形成可靠性结论。

主机测试覆盖统计聚合、四槽到 slot 0 单声道的顺序与符号、BOOT 取消，以及闹钟对等待、
监听、识别和结果阶段的状态抢占。目标板矩阵只稳定命中可观察的监听阶段；准备和应用层
识别交接窗口很短，不把人工碰巧命中写成已验证。结果显示阶段的闹钟抢占、真实 codec、
MultiNet 推理、任务调度和报警声音时序仍需单独实机观察。缺模型整机降级也不属于本矩阵；
采集器会在模型未就绪时明确退出，该兼容路径应使用专门的缺模型安装测试验证。

电池供电下的 `SAVING | MANUAL`、`SAVING | LOW BAT` 与低电峰值另行执行，至少各完成一次
主动语音并用外部仪表观察。USB 汇总中的性能锁释放成功只证明 API 返回成功，不能代替
CPU 频率、电流或 brownout 的实测证据。

## v0.25.0 启动恢复候选验收

本轮把异常启动保护、恢复页面、精简门户、天气页手动刷新和 OTA 确认门槛作为一个候选
范围；本节是验收要求，不代表目标板已经通过。

纯逻辑测试至少覆盖：

1. 同一应用指纹、上一启动仍在健康门槛内且收到 fault 复位时递增计数；第 3 次 fault 后的
   下一次启动选择恢复，计数饱和不回绕；
2. 计划内软件重启不计数；正常断电、棕断、USB/JTAG 等非 fault 复位和应用指纹变化清除
   旧序列；手动恢复不额外增加故障次数；
3. 健康判定只在普通模式、显示与按键初始化成功、首轮周期任务完成、至少渲染一个页面且
   运行满 60 秒后清除计数；只有健康接口能够把记录推进到健康阶段；
4. 待验证 OTA 在相同启动里程碑齐备且运行满 15 秒后才允许首次确认，失败后的下一次尝试
   至少间隔 5 秒；恢复模式始终拒绝确认；
5. 恢复页面只允许“在线更新”和“设置”，短按 `KEY` 在两页间切换，`BOOT` 和 30 秒超时
   不退出；页脚、长按阈值和普通页面状态机保持一致；
6. 恢复门户只注册状态、Wi-Fi 更换/清除和 OTA 上传接口；普通偏好、天气、对话、图片、
   手机校时与恢复默认接口不可访问；
7. 天气页按住 `KEY` 2 秒触发一次显式刷新，提前松开取消，刷新中不重复排队，短按导航仍
   保持原语义；
8. 目标适配层使用主机桩运行真实的 RTC 记录代码，验证跨模拟复位的校验、指纹、启动阶段、
   健康状态、计划内重启标记一次性消费，以及健康标记和计划重启两种先后顺序；
9. 恢复启动禁止自动首次配网，显式重新配网仍可用；无凭据不占用恢复门户的维护入口。

目标板候选验收还需注入未计划软件复位、panic 和看门狗故障，观察恢复原因与上次阶段；
分别覆盖自动恢复、`KEY` + `PWR` 手动恢复、按键初始化不可用时自动开放精简门户、在线
更新、离线本地 OTA、正常断电退出恢复，以及 `BOOT` + `PWR` 仍能进入 ROM 下载模式。
同时通过串口确认待验证镜像的 15 秒延迟确认、5 秒失败重试和 60 秒健康清零。天气手动
刷新需分别在 `NORMAL`、`SAVING`、断网、有缓存和无缓存条件下验收页面与网络收尾。

未保存 Wi-Fi 且按键初始化失败时，自动恢复门户应在网络进入空闲状态后开放，启动失败后
可重试；恢复门户超过 5 分钟仍应可用，普通设置门户继续按原 5 分钟规则关闭。通过
`GET_BOOT` 可读取主任务最近检查点的栈余量与 USB 控制台自身栈余量，两者分别命名，不应
把控制台任务的采样误写成主任务实时数据。

已有 Node.js 的开发环境还可运行 `node tests/test_recovery_portal.mjs`，直接检查固件内嵌
恢复页面的 JavaScript，并验证已配网、未配网和旧配置不可读时上传 OTA 都能取得会话令牌。
该检查不需要安装浏览器依赖，也不能代替目标板 HTTP 服务与无线连接验收。

### 天气日期与缓存时间

`0.25.0-dev.2` 在天气顶栏显示 RTC 当前月日和星期，把 QWeather 数据获取时间移到底部。
日期复用现有 RTC 快照与日期变化重绘条件，不新增网络请求、定时任务或每秒刷屏，也不
改动天气解压与启动路径。

主机测试覆盖一周七天、跨年、普通闰年与世纪年、无效 RTC、非法日期、小缓冲区，以及
“今天已跨天但缓存仍是昨天”时的日期、来源时间和预报标签。布局检查需确认最长月日、
长城市名、缓存过期和更新中提示不遮挡；当前日期始终独立于天气请求状态。

目标板仍需确认正常天气、断网缓存与首次获取失败时顶栏均可读；RTC 无效时应显示
`--月--日  周-`，日期跨天或校时后应更新。不要把本地主机测试和效果图检查记为实机验收。
