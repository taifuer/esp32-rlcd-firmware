# 开发与发布流程

## 技术栈

- 只使用原生 ESP-IDF，不维护 Arduino 构建路线。
- 当前固定 ESP-IDF v5.5.3，目标芯片为 ESP32-S3。
- 项目源码按 ESP-IDF 组件拆分在 `src/`，应用入口位于 `src/app/`。
- 网络功能独立位于 `src/network/`，使用 ESP-IDF Wi-Fi、HTTP Server、NVS 与
  ESP-NETIF SNTP API。
- 设备偏好与电源策略位于 `src/settings/`；偏好保存在独立 NVS 命名空间，纯策略逻辑由
  主机测试覆盖。
- 固件更新独立位于 `src/update/`：在线更新使用 HTTPS 清单、ESP-IDF CA 证书包和受控的
  HTTP Client/OTA 写入流程；设置门户使用受实体按键控制的临时网页，承载偏好、手机校时、
  清除 Wi-Fi、本地 OTA 和可选 microSD 图片管理。两种 OTA 路径共用双 OTA 分区与回滚。
- 音频驱动与诊断位于 `src/audio/`，使用板载 ES8311、ES7210、ESP-IDF I2S 和只保存于
  PSRAM 的非阻塞临时回放状态机。
- microSD 图片源使用 ESP-IDF 原生 1-bit SDMMC 和 FatFs；`src/sd_image/` 负责启动
  扫描、PSRAM 缓存和只在用户确认时开放的有界导入事务，PBM/BMP 单色图片校验
  与解码位于 `src/image/`。
- `src/gallery/` 使用 HTTPS 固定清单下载公共演示图，限制主机、路径、清单大小、
  图片数量和总大小，每张图直接流入 microSD 导入事务并校验 SHA-256。
- U8g2、微雪 ST7305 适配器、Espressif QR Code 和 `esp_codec_dev` 作为外部构建依赖使用。

固定版本见 `tool-versions.env`。如果需要升级依赖，必须同时更新版本/提交哈希、重新完整
构建、实机验收并记录到 CHANGELOG。

涉及页面、提示语或实体按键的改动，应先阅读
[产品界面与交互设计规范](design-guidelines.md)，并同步更新界面效果图和主机逻辑测试。

## 依赖与版本控制

版本库只保存项目源码、文档、辅助脚本，以及由这些源码和固定开源依赖构建并经过实机
验证的发布固件。以下内容
由开发环境按需准备，不提交到版本库：

- ESP-IDF、编译器工具链和 Python 环境；
- U8g2、微雪示例、Espressif QR Code 等第三方源码；
- `build/`、`sdkconfig` 等本机构建结果；
- 社区固件和其他外部预编译文件。

第三方组件的来源、固定版本和许可索引记录在[第三方软件与字体声明](../NOTICE.md)，完整
许可文本保存在 [`LICENSES/`](../LICENSES/)。这些文件是二进制分发所需的合规文档，
不是第三方源码。发布固件只有在源码构建和实机验收均通过后，才能加入 `dist/vX.Y.Z/`。

`dist/` 按版本保存可追溯的发布文件；面向普通用户的 GitHub Releases 页面只保留最新
正式版本。自 v0.2.0 起，每个 `dist/vX.Y.Z/README.md` 还应展示该版本自己的效果图。

### 外部依赖目录

脚本按以下顺序选择依赖根目录：

1. 环境变量 `RLCD_DEPS_DIR`；
2. 当前 WSL 工作区中已存在的共享外部依赖目录；
3. 独立克隆仓库旁的 `../esp32-rlcd-firmware-deps/`。

`bootstrap.sh` 会输出最终选中的绝对路径，并且只写入该仓库外目录，不会把依赖复制到
版本库中。项目禁用 ESP-IDF Component Manager 的隐式下载；所有外部组件均由该脚本按
`tool-versions.env` 的提交哈希准备。

## 常用命令

```bash
./scripts/bootstrap.sh --check
./scripts/configure.sh
./scripts/check-repository.sh
./scripts/check-licenses.sh
./scripts/test.sh
./scripts/build.sh
./scripts/package-release.sh vX.Y.Z
./scripts/flash.sh --port COM5 --confirm
./scripts/update-app.sh --port COM5 --confirm
./scripts/set-rtc.sh --port COM5
```

具体步骤见[开发烧录指南](flashing.md)，不从聊天记录还原命令。

`configure.sh` 调用固定版本 ESP-IDF 的 `menuconfig`，修改写入已忽略的本地 `sdkconfig`。
项目可公开的默认值保存在 `sdkconfig.defaults`；个人固定热点密码不得写入该文件或提交到
Git。删除 `sdkconfig` 后会恢复项目默认值。

`package-release.sh` 在 `build/release/vX.Y.Z/` 生成待上传文件，包括固件、校验值、
`LICENSE`、`NOTICE.md` 和完整许可文本压缩包，并在返回成功前自检全部附件。它不会创建
或修改 GitHub Release，也不会更改仓库可见性。

### 构建版本与更新通道

仓库默认构建版本为 `0.16.0`。需要构建其他版本时，通过环境变量覆盖，不直接为一次
候选构建修改 `CMakeLists.txt`：

```bash
RLCD_PROJECT_VERSION=0.17.0-dev.1 ./scripts/build.sh
RLCD_PROJECT_VERSION=0.16.0 ./scripts/build.sh
```

版本必须是固件可比较的 SemVer，且不带文件名使用的前导 `v`：

- 设备默认读取 `https://mcu.taifua.com/esp32-rlcd/firmware/stable.json`；只有设备偏好中
  显式启用开发者测试通道后才读取 `testing.json`；
- SemVer 不自动选择通道。稳定清单只允许 `0.16.0` 这类正式目标，测试清单用于
  `0.17.0-dev.1`、`0.17.0-rc.1` 等候选，也可在转正式期间指向正式目标。

预发布验证先上传版本化 `-ota.bin`，核对大小和 SHA-256，再更新 `testing.json`。正式
发布必须从同一份已实机验收的源码构建正式版本，重新核对产物差异、大小与 SHA-256 后
更新 `stable.json`；不要让清单提前指向尚未上传或尚未验收的文件。v0.9.0 没有在线更新
客户端；这类设备可从原本地更新入口直接上传当前正式 OTA，也可通过 USB 写入。

## 版本发布清单

1. 确定 SemVer；正式构建必须显式使用 `RLCD_PROJECT_VERSION=X.Y.Z`，并确认版本不含
   预发布标识。设备默认读取 `stable.json`；只有显式加入 Beta 的设备读取
   `testing.json`。
2. 在 `CHANGELOG.md` 把 `[Unreleased]` 内容整理为对应正式版本。
3. 执行 `./scripts/bootstrap.sh --check`。
4. 执行 `./scripts/check-repository.sh`，确认仓库边界、文档链接和历史发布哈希正常。
5. 执行 `./scripts/check-licenses.sh`；新增或升级组件、字体时先更新 `NOTICE.md`、
   `LICENSES/` 和检查脚本。
6. 执行 `./scripts/test.sh`，确认纯逻辑测试通过。
7. 执行 `RLCD_PROJECT_VERSION=X.Y.Z ./scripts/build.sh`，确认无编译错误且应用描述中的
   版本正确。
8. 核对 `build/SHA256SUMS`。
9. 首次迁移使用 Factory 镜像完整烧录；后续同时验证在线更新、设置门户本地 OTA 和保留
   NVS 的串行应用更新，具体步骤见[开发烧录指南](flashing.md)和
   [固件安装与更新](firmware-update.md)。
10. 验证屏幕、RTC、农历、温湿度、电池 ADC、PSRAM 和串口日志。
    含联网功能的版本还必须验证首次配网、错误密码恢复、自动 SNTP、RTC 写后回读、断电
    重连、`GET_NETWORK`、USB `RESET_WIFI`、系统中心页面和上下文长按操作，并确认日志
    不包含家庭 SSID 或密码。含 microSD 改动的版本还必须分别验收无卡、只读启动、
    用户确认导入、中断恢复、数量上限和关机插拔。
11. 只有实机通过后，才把 Factory 与 OTA 两个镜像复制到 `dist/vX.Y.Z/`，并保存各自
    大小、SHA-256、构建依赖和验收记录。
12. 按[发布固件安装指南](user-install.md)重新执行发布路径，确认普通用户命令和文件名一致。
13. 执行 `./scripts/package-release.sh vX.Y.Z`，检查 `build/release/vX.Y.Z/` 中的全部附件
    和 `RELEASE_SHA256SUMS`。
14. 检查 Git 暂存内容，确保没有第三方源码、`build/`、`sdkconfig`、密码或外部固件。
15. 提交并创建 `vX.Y.Z` 标签。
16. 创建 GitHub Release，上传打包目录中的 Factory/OTA 固件、校验文件、效果图、
    `LICENSE`、`NOTICE.md` 和许可文本压缩包。
17. 把同一 OTA 固件发布到版本化 HTTPS 地址，核对远端大小和 SHA-256 后再原子更新
    `stable.json`；不得让正式清单指向测试文件。
18. 用上一正式版本在线检查并确认能发现新版本，但安装仍需实体按键确认。
19. GitHub Releases 只保留最新正式版本；删除旧 Release 条目时保留 `dist/` 历史文件。
20. 仓库可见性是独立的人工决定；构建、打包和发布脚本均不得自动切换 Public/Private。

## 安全约定

- 构建与烧录是两个明确分开的动作。
- 烧录必须显式传入 `--confirm`，且脚本必须验证目标 VID/PID。
- 不默认执行 `erase-flash`。
- 家庭 Wi-Fi 密码不得写入源码、构建配置、构建日志或 Git；运行时凭据只允许由配网页面
  写入设备 NVS。临时配网热点可在已忽略的本地 `sdkconfig` 中设置固定密码，但默认应
  留空并在运行时随机生成；固定值会嵌入固件，不应视为秘密。当前 NVS 未加密，这一限制
  必须在面向用户的文档中明确说明。
- 任何配网或网络日志都不得输出家庭 SSID、密码或 HTTP 请求正文；调试状态只报告是否
  已配置、状态名、错误码和非敏感长度。
- 二维码原文包含临时热点密码；外部组件的输入日志必须在编译时关闭，`build.sh` 会检查
  最终组件归档，发现相关日志字符串时拒绝生成可用构建结果。
- 在线更新必须通过 ESP-IDF CA 证书包验证 HTTPS；清单的项目、硬件、通道、版本、下载
  主机、大小和 SHA-256 任一不匹配都不得写入或切换启动槽。安装前必须重新读取清单，
  自动流程只能检查，不能下载或安装。
- 不改写或提交仓库外的上游参考源码。

## 网络功能验收

当前网络设计与操作说明见[自动配网与网络校时](network-time.md)。正式发布前至少覆盖：

1. 空白 NVS 启动后屏幕显示默认热点名称、随机密码和固定入口地址；另外验证自定义名称、
   关闭设备后缀与固定密码配置；
2. Android 和 iOS 扫描二维码均能识别热点名称和密码；特殊字符转义正确，二维码四周
   静区完整，扫码后也可按文字信息手动连接；
3. 手机连接临时热点，提交开放网络和 WPA2/WPA3 Personal 凭据的正常/错误边界；
4. 正确凭据下取得 DHCP 地址，SNTP 按设置的 UTC 偏移取得本地时间，PCF85063 写入后
   秒数持续增加；默认偏移为 UTC+8；
5. 家庭 Wi-Fi 离线时首屏、RTC、月历、温湿度、按键和音频保持可用，不自动开放配网
   热点。`NORMAL` 及实际生效为 `NORMAL` 的 `AUTO` 使用 1、5、15、60 分钟退避；
   Wi-Fi 已连接但 NTP 不可达时标记为不同失败阶段，同样不打断首屏。`SAVING` 及实际
   生效为 `SAVING` 的 `AUTO` 不自动联网或重试；错误凭据只能通过用户明确执行重新配网
   来替换；
6. 新判定记录首次显示 `RTC BACKUP: UNTESTED`；安装 RTC 备用电池并真实断电后，在任何
   NTP 操作前显示 `VERIFIED`，移除或耗尽备用电池后的真实断电显示 `FAILED`；两种情况
   都保留 NVS 网络凭据并按需自动恢复时间；
7. USB `RESET_WIFI` 与设置门户中的“清除 Wi-Fi 配置”都只清除项目网络命名空间，并在
   不重启设备的情况下进入首次配网；门户必须二次确认，且不会重置其他偏好；
8. `BOOT` 默认在首屏与月历之间切换，microSD 存在有效图片时条件加入
   图片页。`BOOT` 能从任意系统页返回首屏；`KEY` 只进入并循环
   “状态、音频、设置、在线更新”四个系统页，所有次级页面 30 秒超时符合规范；
9. “状态”页长按 `KEY` 2 秒触发即时校时；“音频”页长按 2 秒执行扬声器、双麦克风和
   最长 5 秒临时回放测试；“设置”页长按 `BOOT` 2 秒切换省电策略，长按 `KEY` 3 秒开启
   设置门户。音频录制/回放中短按 `KEY` 可停止、活动阶段短按 `BOOT` 可取消且清除
   PSRAM 数据；其他页面未提示的 `KEY` 长按以及“设置”页之外的运行时 `BOOT` 长按均无
   操作，松开也不会误判为短按；
10. “在线更新”页按住 `KEY` 2 秒可检查；发现新版本后再按住 2 秒进入 `REVIEW`，确认页
    必须按住 3 秒才安装。自动联网只更新检查结果，不切换页面、不下载且不静默安装；
11. 所有版本默认接受 `stable.json`，显式启用开发者测试通道后才接受 `testing.json`。
    稳定通道不得提供预发布目标；错误项目、硬件、通道、版本、最低版本、URL 主机、大小
    和 SHA-256 均被拒绝，同版本与降级也不安装；
12. 在线检查、连接和确认阶段短按 `BOOT` 可以取消；写入开始后按键不再中断。正确 OTA
    镜像显示实际百分比、校验后重启并保留 NVS/Wi-Fi；断网、截断响应和摘要不匹配仍保留
    当前启动槽；故意不确认的新镜像能由 Bootloader 回滚；
13. 设置门户可保存 `AUTO/NORMAL/SAVING`、UTC 偏移、摄氏/华氏单位、播放音量、每周
    闹钟和更新通道，可用手机时间写入 RTC，也可清除 Wi-Fi 配置；默认运行模式为 `AUTO`、
    更新通道为稳定版、闹钟默认关闭。schema v4 记录迁移到 v5 时，旧 raw `NORMAL(0)`
    与 `SAVING(1)` 均保留原选择，其他偏好保持不变；单槽损坏后
    启动会读取完整槽并修复冗余，健康双槽启动不重复写入；保存和破坏性操作均须按页面
    说明确认；
14. `NORMAL` 显示秒并按 1 秒读取 RTC、5 秒读取环境、30 秒读取电池，同时允许自动校时、
    网络重试和版本检查；`SAVING` 不显示秒，通常按 60 秒、60 秒和 5 分钟读取 RTC、环境
    和电池，且不自动联网；`AUTO` 根据电量选择这两套实际策略，处于省电状态时每 60 秒
    读取电池以便及时判断恢复。启用闹钟后只把 RTC 检查提高到每秒一次，不增加屏幕刷新。
    三种配置模式的按键、音频、手动校时、设置门户和手动更新都可用，固件不得使用
    Light-sleep 或 Deep-sleep；
15. 单个闹钟按设置时区下的 RTC 本地时间和每周掩码触发；`AUTO/NORMAL/SAVING` 与
    断网时都能响，`BOOT` 停止、首次 `KEY` 延后 5 分钟、第二次不再延后、60 秒自动停止；
    RTC 无效、错过目标分钟和物理关机期间不补发，同一规则同一天重启不重复响；闹钟模态
    期间原先已按住的按键不会误触发，临时音频诊断会安全结束，设置门户或 OTA 不会让
    RTC 读写交错；
16. 设置门户能够从同一临时热点上传 `-ota.bin`；短按 `BOOT` 能在等待上传时安全取消，
    上传错误文件和中断传输不会改变当前启动槽，无互联网时仍可完成本地 OTA；五分钟截止
    后拒绝新请求，已开始的短设置事务在有限清理窗口内完整结束，长 OTA 到期后中止且不切槽；
17. 关机后按住 `BOOT` 再按 `PWR` 仍能正常进入 ROM 下载模式；此时应用未运行，屏幕不
    显示写入进度；
18. Factory 镜像重新烧录后 NVS 被清空并能重新完成首次配网；在线更新、设置门户本地
    OTA 和 `update-app.sh` 串行更新后 NVS、家庭 Wi-Fi 与设备偏好保留；
19. 空白 NVS 的配网二维码 60 秒后恢复离线首屏，临时热点在 5 分钟后关闭；RTC 无效时
    首屏稳定显示占位符，系统中心和其他本地功能仍可操作；
20. 串口和构建产物的字符串检查不包含实机家庭 SSID、家庭密码或二维码中的临时热点密码。

纯逻辑表单测试由 `./scripts/test.sh` 执行。网络驱动、DHCP、HTTP、SNTP、NVS 和 RTC
联动无法由 WSL 主机测试替代，必须在目标开发板上验收。

## v0.12.0 microSD 验收

`0.12.0-dev.1` 完成无卡启动、16 GB FAT32 挂载和 PBM 图片显示的实机验收，
并在验收后以同一功能源码正式发布为 v0.12.0。存储卡准备和文件格式见
[microSD 图片准备](microsd-images.md)。

1. 空卡槽正常启动，不显示 microSD 全屏错误；`BOOT` 保持“首屏 → 月历 → 首屏”，
   RTC、农历、传感器、音频和系统中心都可用；
2. 物理关机后插入 16 GB FAT32 microSD，固件通过 1-bit SDMMC 只读挂载，

   稳定排序，跳过损坏文件后选择第一张有效图片，不因目录枚举顺序改变；第 33 个
   受支持候选使图片页隐藏并记录超限原因；
4. 400 × 300 PBM P4 与受限的未压缩 1-bit 黑白 BMP 正确解码；错误尺寸、灰度、

7. 无 FAT32、缺少目录、空目录、全部文件无效和挂载失败均隐藏图片页；详细原因

8. 运行中插卡不得暗示已支持热插拔，关机重启后才识别；关机拔卡后重启恢复两页

9. 电脑端转换工具默认生成 PBM P4，按比例适配顶部 400 × 250 可见区并保留

目录扫描、候选选择、PBM/BMP 校验、像素极性、页面环和超时必须有纯逻辑主机测试。

## v0.16.0 图片页安全删除验收

本节记录 v0.16.0 的设计与验收边界。

1. 图片页普通短按 `KEY` 保持原有多图切换或单图进入系统中心；持续按住 1 秒出现提示，
   此后未满 2 秒松开只取消长按，不切图也不进入系统中心；
2. 满 2 秒只打开仍显示当前图片及 `n/N` 的确认页，同一次长按必须完整松开，之后短按
   `KEY` 才删除，短按 `BOOT` 或 10 秒无操作取消；
3. 确认目标使用目录修订号与精确文件名固定；等待期间由网页选择、导入或删除图片时，
   本次确认安全取消，不会删除后来显示的另一张图片；
4. 删除由独立任务执行，屏幕显示 `DELETING` 并提醒保持供电；任务期间两个按键不落入
   页面导航，RTC、闹钟调度和其他主循环工作保持响应；
5. 成功或失败反馈至少保持 2 秒。成功后选择相邻图片，删除末尾时回到第一张，删除最后
   一张后图片页隐藏并回首屏；失败时文件、当前图片和运行时目录不变；
6. 闹钟在确认阶段出现时取消确认，在已经开始删除后出现时优先覆盖删除界面，但后台任务
   继续完成，闹钟结束后仍能看到完整时长的删除结果；
7. 设置门户导入或删除占用 microSD 时，本机删除安全失败并提示稍后重试；不格式化、批量
   删除、热插拔重扫，也不因成功或失败而重启设备；
8. 操作过程中按住任一按键跨越取消或结果页边界时，必须先松开并重新按下，不能把释放
   事件误判为普通短按。

`./scripts/test.sh` 覆盖长按动作映射、1 秒后松开取消、原长按松开无短按事件、二次短按
确认、确认/取消、10 秒超时、2 秒结果、计时饱和和目标快照变化；既有图片删除策略测试
覆盖下一张选择、末张回到首张和最后一张。`0.16.0-dev.1` 已通过隔离的测试通道从
v0.15.0 完成在线更新，用户确认在线升级与本版功能未见问题，作为 OTA 和图片删除正常
路径的整体冒烟验收。慢卡、只读卡、强制写入失败和写卡期间触发闹钟未逐项进行破坏性
实机验证；删除状态机、目标快照和选择策略已有主机测试，SDMMC、真实介质联动及闹钟
抢占不在集成主机测试覆盖范围。

## v0.17.0 自动低功耗验收计划

本节面向尚未发布的 v0.17.0。主机测试能够确认纯逻辑和记录迁移，但不能替代目标板上的
频率、外设联动与电流测量；以下项目完成前不得把低功耗效果描述为已完成实机验收。

1. 空白 NVS、恢复默认值和首次打开设置门户时均选择 `AUTO`；门户可保存
   `AUTO/NORMAL/SAVING`，设备 `SETTINGS` 页在 `AUTO` 下同时显示配置策略与当前实际
   生效的 `NORMAL` 或 `SAVING`；
2. 从 v0.16.0 的 schema v4 双槽分别准备旧 raw `NORMAL(0)` 和 `SAVING(1)` 设置，经 OTA
   升级后确认前者仍为 `NORMAL`、后者仍为 `SAVING`，时区、温标、音量、更新通道与
   闹钟规则不变；新 schema v5 双槽完整，单槽损坏仍可回退，迁移中断不会把 schema 标记
   提前推进或以默认值覆盖有效的 `cfg4_a` / `cfg4_b`；
3. 显式 `NORMAL` 始终使用原正常策略，显式 `SAVING` 始终使用原省电策略，电量跨越阈值
   不得改变这两种手动选择；切换任一配置模式均原地生效，设备不重启，RTC 时间、页面、
   闹钟规则和已保存网络配置连续保留。从手动模式切换到 `AUTO` 时，若已有有效电量，
   不高于 20% 立即使用 `SAVING`，不低于 25% 立即使用 `NORMAL`，21%—24% 保持此前
   实际模式；若电量暂时无效，则保留此前实际模式作为滞回基线，后续读数按运行期连续
   确认规则处理，不重新套用冷启动首样本规则；
4. `AUTO` 冷启动在取得首个有效电量前先保持 `NORMAL`；首个有效读数不高于 20% 时
   直接使用 `SAVING`，高于 20% 时使用 `NORMAL`，重点核对 20% / 21% 边界；
5. `AUTO` 运行期间从 `NORMAL` 进入 `SAVING` 必须连续两次取得不高于 20% 的有效读数，
   从 `SAVING` 恢复 `NORMAL` 必须连续两次取得不低于 25% 的有效读数。21%—24% 保持
   当前实际模式；未达到待切换阈值的读数、无效读数或读取失败会打断未完成的连续计数，
   防止临界值抖动；
6. `AUTO > SAVING` 检测到发送 USB 数据帧的电脑主机时立即恢复 `NORMAL` 并取消低电待
   切换计数；不再检测到主机后立即读取一次电量，再按新的连续样本判断。分别用电脑数据
   连接、墙充、充电宝和纯充电线验证边界：后三者因原板没有 VBUS/充电状态输入而不得误报
   为数据主机，仍按电量策略运行；显式 `NORMAL`、`SAVING` 保持用户选择；
7. 实际模式切换时，秒显示、RTC/环境/电池采样、自动联网、后台更新检查和 CPU 策略同步
   切换，不生成重启；`AUTO > SAVING` 每 60 秒读取电池，显式 `SAVING` 仍按 5 分钟读取；
8. 目标板启动日志确认 ESP-IDF 动态频率范围为 80—240 MHz。实际 `NORMAL` 持有最高频率
   锁并保持 240 MHz，实际 `SAVING` 释放该锁以允许 DFS；反复跨模式切换时锁状态和日志
   一致，不发生死锁、错误累积或任务停顿；
9. 所有模式均保持 Light-sleep、Deep-sleep 和自动 Tickless Idle 关闭。按键、USB
   Serial/JTAG、屏幕刷新、RTC 闹钟、音频、microSD、设置门户以及本地/在线 OTA 按既有
   验收路径回归，`SAVING` 不得被描述为会关闭全反射屏或使本地功能不可用；
10. `./scripts/test.sh` 覆盖三态模型与表单、schema v4 raw 值迁移、schema v5 编解码、
    冷启动边界、20% / 25% 滞回、连续两次确认、无效采样复位、USB 数据主机优先级和显式
    模式固定策略；ESP-IDF 正式构建还需确认 PM 配置、组件依赖和 240 MHz 上限断言通过；
11. 在断开 USB、仅由受控电池供电的统一条件下，使用外部电流表或功耗分析仪分别测量
    `NORMAL`、`SAVING`、`AUTO > NORMAL` 与 `AUTO > SAVING`。记录稳态电流、联网与
    屏幕刷新峰值，并覆盖闹钟开关、microSD 有无、Wi-Fi 任务、设置门户和音频空闲；只有
    取得可复现数据并明确电池容量后才估算续航，本项目前仍视为外部仪表待验收。
12. 在 `SETTINGS` 页按住 `BOOT` 1 秒显示明确提示，满 2 秒只切换并保存一次
    `AUTO` → `NORMAL` → `SAVING` → `AUTO`；提示出现后未满 2 秒松开、继续长按或长按后
    松开均不得触发返回首屏。操作不启动热点、不重启，保存后立即尝试热应用并保持页面；
    应用成功后才显示完成，暂时无法应用时明确显示等待重试，保存失败时原配置和运行态不变。
    保存前必须重新读取最新完整设置，只修改电源策略，避免覆盖门户刚保存的时区、温标、
    音量、更新通道或闹钟。原 `KEY` 短按切页、按住 3 秒开启门户以及其他页面的长按动作
    保持不变；两个按键交叠按下时不得同时切换策略和开启门户，结果页期间开始的任意按键也
    必须完整松开后才能恢复普通操作。
